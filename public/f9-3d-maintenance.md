# F9：3D 美术迭代与维护成本评估

日期：2026-09-14

建议继续 3D。初期场景、镜头和动画调试的开发消耗更高，但采用有限镜头、模板化卡匣、模块化设施后，日常内容维护可以控制。

## Token 与运行成本

这版原型由浏览器和显卡渲染，设施操作使用本地代码，不调用 AI。玩家转镜头、战斗和建造不会产生模型 token 消耗。模型/贴图下载、内存与 GPU 是另一类成本。

让 AI 开发时，读取代码、理解空间、生成修改、查看工具结果和截图都会消耗 token。3D 增加相机、材质、光照、遮挡和动画之间的关系，初期更容易反复调试。正式资产制作也需要美术工时，不能仅用 token 衡量。

官方用量说明指出，任务复杂度、上下文、模型、推理、工具和缓存都会影响用量。代码行数和提示词长度不能直接换算实际费用。缺少同类任务实测样本，不能承诺固定 token 数或“3D 恒定是 2D 的几倍”。

来源：[OpenAI 官方用量说明](https://learn.chatgpt.com/docs/pricing)

## 按未来任务评估

| 改动 | 相对开发负担 | 控制方式 |
|---|---|---|
| 卡牌数值、冷却、设施配方 | 低，与 2D 接近 | 使用独立规则数据 |
| 同类卡牌、卡图替换 | 低至中 | 复用卡匣、材质与 UI 模板 |
| 同类设施、布局和灯色 | 低至中 | 复用模型族、导轨和镜头预设 |
| 新结构设施、异常房间 | 中至高 | 新资产和空间验证，先完成一个代表场景 |
| 精细手部、骨骼角色、复杂转场 | 高 | 制作动画资产，再由代码调用 |
| 自由移动、碰撞和复杂物理 | 高且持续 | 在核心玩法需要时再增加 |

这里的高低是工程判断，不是实际 token 测量结果。

## 当前项目的具体判断

战斗规则已与表现分开，这次左右转上下主要修改相机、纹理朝向、冷却条和 HUD，不涉及伤害结算或冒险存档。但旧 3D 房间组件包含较多程序化造型代码，继续堆积会增加定位成本。

基地原型将内容拆为设施数据与状态、公共材质/几何工具、设施模型、相机与场景交互。新增配方无需读灯光代码，调整材质无需改生产规则。

正式美术建议用 Blender 等工具制作 GLB 模型及动画，代码只负责装配和调用。长期让 AI 手写每颗螺丝、布褶和手指关键帧，既增加上下文，也限制品质。

## 维护约定

1. 战斗固定敌方在上、我方在下；三路从左至右为 I、II、III。相机保留入席与战术两套预设。
2. 卡匣、设施机壳、仪表、管线、标签和材质共用模板；规则数据独立。
3. 每次迭代提出可观察问题和验收画面，例如“上方卡牌可读”，减少模糊要求导致的往返。
4. 保存关键镜头与验证步骤；按改数值、同类内容、新场景分别记录真实用量、模型与迭代次数。
5. 先完成有限镜头下的品质，再考虑自由移动、完整身体动画和复杂物理。

## 这次基地原型

包含舱内、建造和近看视角；拖动环视与缩放；发电机、医疗舱、培育舱、设备台、储藏架五种设施；实体安装预览；外观升级；拆除返还；一次/日生产；休息；服务导轨展开；舱门开合与应急照明。

这是独立美术沙盘，经济数值为演示配置，升级只改变外观，不读写冒险存档。程序化造型用于验证空间与交互，尚非正式高精度美术资产。
