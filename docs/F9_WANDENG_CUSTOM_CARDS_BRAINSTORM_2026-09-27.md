# 自制旧物与自由模式：脑暴 v0

日期：2026-09-27。状态：用户提出方向，助手方案待讨论，**尚未实装**。

## 用户给出的方向

- 通关一局后解锁自由模式。
- 玩家可自行制作卡牌、上传图案；AI 为其生成名称、文本和技能效果。
- 必须设立平衡基线，控制自制卡强度。
- 在战斗玩法恢复后再讨论，不能借此继续更改原 F9 战斗基线。

## 判断

这个方向最有价值的是“让我自己的物品在游戏里活过来”。万灯城的物灵、遗忘与记忆为这种参与提供了主题依据。上传爷爷的旧杯子、旅行中买的闹钟、自己画的工具，都比只换一张卡图更能形成所有感。

核心风险：若图案最后总映射到极少数模板，会只剩换皮；若让模型自由写代码和裁定数值，则无法稳定执行、解释、回放与约束组合。建议把创作权和规则裁定权分开：模型提出“这是什么、经历过什么、希望怎样行动”，规则系统完成“能否实现、合法参数及边界”。

世界观不必改成物灵者凭空造灵。可包装为“归物所工作间”：物品原本有灵，玩家提交的是一件旧物的档案与记忆，AI 协助把其特性表达为战斗能力。具体命名待定，不提前替用户定案。

## 玩家流程建议

1. 通关并完成送达后，收到使用归物所工作间的邀请。
2. 上传图案，另可写一句物品的记忆；系统建议 2–3 个方向供选择，而非把视觉识别当成唯一真相。例如旧杯子可以表达保温、分享、脆弱但被珍惜。
3. 先选它的性格/战斗方向：保护同伴、储存后释放、冒险爆发等。AI 生成名字、短故事和机制草案。
4. 展示 2–3 张机制明显不同、占格和预算明确的候选卡。编辑图文不增加预算；添加强效果须同时接受冷却、占格、弹药、作用范围等代价。
5. 在试炼桌看实际运转、配合和复盘。允许一键选择“更专精”“更稳定”“更依赖伙伴”等修订方向，不要求玩家理解底层公式。
6. 定稿保存卡牌蓝图，进入自由模式的卡池；局内从基础状态培养。以后重开保留蓝图，不保留上一局养成数值。

建议首版每局最多带入 1–2 张自制蓝图，其余仍从基础卡池获取，使收集与构筑继续有意义。数量是待验证假设，不是已定规则。自由模式的不同蓝图版本分别存档，不在玩家进行中的对局里静默改数值。

## 平衡建议：三道约束，不能只靠一个总分

### 1. 有类型的机制词库

优先开放原引擎能够清楚表达的效果：直伤、灼烧、侵蚀、修屏、治疗、有限的相邻配合与冷却推进。组合仍可产生新牌，但不能凭空引入时间回滚、复制任意技能、无限递归等无法评估的语义。

AI 输出有限的数据结构（触发、条件、目标、效果、参数、次数边界），由规则层校验和编译。先确定可执行能力，再从同一结构生成规则文本；名字/故事可自由创作，不能让风味文本悄悄改变能力。AI 不生成或执行任意脚本，也不在战斗过程中临时解释技能。

### 2. 多维预算与硬上限

以原 50 张牌作为校准参考，但它们本身还需平衡验证，不能直接把所有现有数值当作合格上限。

按相同等级、品质、稀有度和 1/2/3 格分别建立参照，记录：首轮爆发、10/30/60 秒持续收益、屏障/生命不同目标收益、控制覆盖率、触发频率、成长上限、占格机会成本及对增幅器的利用。

| 类型 | 预算最容易漏算的部分 |
| --- | --- |
| 多段直伤 | 每发触发、额外命中、固定减伤、增幅器封顶，并非只看总伤害 |
| 灼烧/侵蚀 | 状态累积和破屏后的收益，不能把一层等同一点即时伤害 |
| 治疗/修屏 | 有效量、启动时间、封顶与是否需要承伤，不按纸面数字直接加总 |
| 充能/加速/触发 | 放大的是伙伴能力，有反馈回路；尤其要测相互充能与连锁触发 |
| 条件技能 | 条件是否能被低成本长期维持，不能用“有条件”换取过量免费预算 |
| 成长/任务 | 达成速度、战内上限和组合放大，不能只评初始状态 |

基础概念可写成“效果成本之和 + 联动/条件可靠性溢价 ≤ 对应占格与成长档预算”。它是筛选模型，不宣称数学证明平衡。强控制覆盖、单次充能量、最短有效冷却、触发次数等再由硬上限独立限制。第一版暂不开放复制任意技能、无上限减冷却和可自我递归的触发。

### 3. 原引擎试炼与组合检验

固定种子，测试单卡/替换同位置、混合阵容、针对阵容和极端组合；覆盖三路位置、十种增幅器、伤害/持续/治疗/防御/控制流。除平均胜率，观察最高分位、最坏对局、爆发窗、破屏速度、超时僵局、触发次数及预算预估偏差。

加入自动组合搜索，主动寻找互相充能、过量装填、控制锁死等放大漏洞。触发数量异常可直接判非法，但预算合格且测试无异常也只代表进入可用区间，不代表永远平衡。不能让玩家刷 AI 生成次数来赌博更高强度：同档预算不随机，生成次数只增加创意选择。

建议第一期只有受约束的自由模式。若以后开放不受约束的趣味沙盒，必须单独标记，不与挑战记录、正式奖励或未来排行榜混在一起。不要为了“自由”第一期同时做两个体系。

## 具体例子（数值待基线测试）

上传一张有裂纹的保温杯，再写“奶奶一直替我留着热水”。

- 名称候选：留温杯。
- 记忆短句：杯口已经缺了一角，水却总是温的。
- 候选 A：定时治疗；本路屏障仍在时，将一部分治疗预算改为修屏。偏稳定照顾。
- 候选 B：本路屏障实际承伤时，积累有限的温度；周期消耗温度治疗。偏储存反击节奏，有真实风险与上限。

两者不是同时满配。选择 B 的储能潜力，要承担启动慢或更长冷却等代价；“这件物品对我很重要”决定故事，而不换取额外战力。首版可以只支持能由已批准机制结构表达的 A，再按完整测试开放 B。

## 第一轮验证切片

先不用大而全的编辑器：上传一图、写一句记忆、AI 给三张草案、可控调整、自动验证、保存一张蓝图、带入一局并回放。所有定义、资产引用、内容 ID、规则版本与生成结果在开局前冻结；保存与回放读取冻结数据，不能再次请求 AI 再解释一次。

成功标准首先是“我认得这是我的东西，而且愿意带着它玩”；同时检查候选差异是否明显、玩家是否理解代价、坏组合是否被拦截、生成与试炼等待是否可接受。API、模型选型、上传存储、定价与内容审核还未展开，不作为当前已完成能力。
