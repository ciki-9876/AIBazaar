# f9 game · 电梯幸存者设计验收台 v0.2

本轮交付是一套九页设计网站，结合独立交互原型和 PRD，供逐模块验收。原型场景可反复重置，数值属于设计建议；原型之间不共享一局游戏状态。旧版集市战斗原型仍位于根路径。

## 页面索引

| 路径                  | 模块         | 可操作内容                                          |
| --------------------- | ------------ | --------------------------------------------------- |
| `/design/`            | 总览与开局   | 物件调查、两个开场选项、闭环与模块导航              |
| `/design/world/`      | 世界与楼层   | 种子初始化、100 层蓝图、跳层成本、生成失败回退示意  |
| `/design/expedition/` | 远征与撤离   | 推进、搜刮、常规返回、紧急回程、撤离失败            |
| `/design/inventory/`  | 背包与鉴定   | 共享容量、拾取与放下、现场鉴定、重复请求            |
| `/design/cards/`      | 卡牌成长     | 锁定稀有度、品质与强化、拆解返还、不同样本比较      |
| `/design/base/`       | 电梯经营     | 模块槽位、建造、扩建、休息、有限原料生产            |
| `/design/combat/`     | 自动战斗     | 旧引擎冷却与邻接联动、播放暂停、确定性结果          |
| `/design/survivors/`  | 幸存者与账本 | 99 人周期推进、共享库存、先搜刮后首次展开、状态日志 |
| `/design/ranking/`    | 通关与排名   | 到达与通关区分、并列排名、死亡保留成绩              |

每页提供：玩家目标、已确认前提、详细规则、数值建议、数据契约、异常分支、范围说明、关联模块、两个待决策问题、五项验收条件、意见与确认状态。

## 验收记录

- 各模块初始均为待验收。选择待决策项并勾选检查项后，才能明确点击确认。
- 修改已经确认的模块，会将其恢复为待验收。
- 记录使用当前浏览器的 localStorage，键为 `f9.elevator.design.review.v02`。不同网址或浏览器不自动同步。
- 导出按钮生成全部九模块的 JSON；打印按钮用于保存当前页 PDF。
- 选择其他方案记录的是待整合设计意见，原型仍展示本版建议规则，不会动态生成另一套游戏实现。

## 原型实现与后续边界

世界样例使用本地确定性组合器，没有调用真实大模型。生成校验链是架构示意，尚未实现生产级语义验证、模型重试和可解性求解。正式世界需要冻结种子、规则版本、内容哈希，合法效果引用及奖励预算。

背包模型保持鉴定前后携带体积一致；首次扫描生成稀有度，实体记录本身不含稀有度字段。鉴定重复请求重用回执，不重复扣电荷或周期。现场换装的十格与旧牌回包事务列入 PRD，未在背包样例中实现。

撤离样例用固定成功节点表现状态机，失败按钮是明确的验收事件。常规游戏中的事件、谜题、伤势与环境修饰仍需后续接入。

幸存者样例为本地摘要模拟：固定意图与轮换优先级，先位置及遭遇、后存量分配。所有受到机器人影响的楼层都保留轻量账本；玩家到达时才展开详情。日志包含状态快照和资源扣减，可重放验证。未实现服务端并发、掉落物逐件尸体转移及真正近场战斗模拟。

自动战斗复用旧引擎，水果刀等名称是新题材展示映射。它不是已完成平衡的新卡池。

## 验证

`npm test` 包含原有引擎测试和设计模型测试，覆盖世界确定性、容量守恒、鉴定幂等、撤离成绩边界、账本重放、排名与验收数据。

`npm run lint`、`npx tsc --noEmit` 和 `npm run build` 用于静态检查与导出。当前静态输出位于 `dist/client`，包含全部设计 HTML 页面和原游戏。

开发预览：`npm run dev -- --port 3000`，访问 `http://localhost:3000/design/`。Windows 本地构建使用 Node 24.19.0，规避旧版 Node 24.14.0 构建结束时的 libuv 退出错误。

未运行浏览器点击、DOM 或截图测试。WebMCP 工具仅在浏览器提供 `document.modelContext` 时注册；真实 WebMCP 宿主可用性未验证，普通页面交互不依赖该能力。

所有新设定的依据是本次对话。文中的建议不代表用户已经确认，也未将数值样例宣称为完整新游戏。
