# F9 生存房间：可复用的大场景生成方案

当前运行代码：`lib/survival-world.ts`、`lib/survival-room.ts`、`app/survival/environment.ts`。当前生成版本 4，试玩种子 92601；纯本地生成，不需要模型请求。版本 2 增加箱柜碰撞；版本 3 为大维修营地；版本 4 按 [ADR-0010](./design-log/decisions/ADR-0010-human-scale-lift-and-camera.md) 改为现实小轿厢。布局定义在 `lib/survival-lift.ts`，供美术与导航共用，模块选择算法不变。新电梯中心 (48.5,75.5) 对齐导航格中心，0.9 米门洞无需放大；玩家半径 0.28 米，导航网格保留 0.42 米净空检查。

## 配方与输出

输入为整数种子和版本。地图为 96×80 世界单位，按 4×4 组织为 16 个 24×20 模块。模块有稳定身份，选择“水罐＋泵机”“双泵＋备件货架”“隔墙＋双罐”之一，再选择镜像。LCG 只决定配方和镜像；同种子产生同世界。

每个模块保留边界与中央十字通道。机械障碍仅进入四个角区，因此模块拼接后天然连通。出生电梯在南侧中央，驻守者在北区，线圈／锯环／激光器沿入口附近路线布置，其余模块有补给与零件；早期装备教学位置不随种子变化。当前所有配方共享资源与入口锚点，不允许装饰阻断这些位置。

输出包括模块清单、碰撞矩形、刷怪入口。物资与敌人拥有稳定 ID；世界数据与模拟状态可序列化。探索／当前视野是两张 96×80 网格，碰撞和寻路使用同一障碍数据。未来持久化时必须保存版本与已生成布局，不能只保存种子后悄悄更换配方。

箱柜在物资交互锚点后方 0.9 米加入约 1.4×0.9 米碰撞体；锚点本身留给角色接近搜索。容器内容在创建房间时确定，额外物品使用容器 ID 加序号产生稳定身份。开启只改变状态，不重新生成内容。箱柜由动态场景组件绘制，静态环境不会重复建模。

## 为什么节省生成成本

美术只需维护少量机械部件和模块配方。地图扩大或换种子由程序重新组合，运行时模型 token 消耗为零；不为几百件摆设反复生成长文本或单独调用资产生成服务。新增一种主题时主要替换部件库、调色与少量模块配方，不逐房间手写完整场景。

这不意味着 GPU 成本为零。当前渲染复用基础几何，按材质合并静态物体；怪物复用模型模板，离开视野的动态对象隐藏，短期特效结束即释放；导航网格缓存、流场按角色所在格缓存。当前一个完整大型房间常驻，**尚不是无缝多楼层流式加载**。将来更多楼层需要按模块合批、分块加载与独立资源预算。

## 扩展约束

1. 新配方必须留出约定通道，资源锚点、刷怪点可行走且连通；入口和撤离路线必须双向可达。
2. 场景模型的主要体积应与碰撞一致，装饰只能占预留区；不可用不可见碰撞“修复”视觉上畅通的路。
3. 用不同轴线、局部地标、资源组合和敌群节奏增加差异，避免仅靠镜像复制大量房间。
4. 先扩配方库，再引入更复杂的模块连接图；如果加入锁门或单向通道，应重新定义连通验收，不能沿用本版全通假设。

## 当前验证

测试比较相同与不同种子的输出，并在 16 个种子上检查所有资源、驻守者与刷怪入口可行走且从电梯可达。新面积为旧 28×24 的 11.43 倍。视觉验收仍需关注重复感、停留搜索的遮挡风险，以及大房间往返时间是否与生活数值相容。
