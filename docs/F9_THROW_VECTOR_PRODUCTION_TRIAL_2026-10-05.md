# 甩牌美术：SVG试验与量产建议

日期：2026-10-05。

## 用户决定与本轮范围

用户已接受[报刊插画方向](./design-log/decisions/ADR-0046-throw-editorial-illustration.md)，要求尝试SVG并讨论更好的量产方法。风格已经选定；全量改成SVG或采用某个商业动画工具尚未批准。本轮保留首页现版，增加独立对照与可玩试演，没有变更 `magician-adventure-v1`、`throw-duel-v3`、随机流、牌型、抽牌或构筑规则。

- [对照页](http://localhost:4175/art/vector)：同一工作室、同一实时灯光，切换现版与SVG；9件素材并排放大到1／2／4倍，切换原色／夜巡配色，演示主角行走。
- [可玩试演](http://localhost:4175/art/vector/play)：原主线操作链，SVG家具、主角及对应肖像／战斗形象。原三位NPC、装饰与装备图标保留位图；不宣称已完成全游戏矢量化。
- [矢量母版](../public/art-assets/throw/vector-v1/)：8道具×2配色、主角×2配色、2图集，共20个SVG；[制作清单](../public/art-assets/throw/vector-v1/production.json)记录源文件与限制。
- [母版组件](../apps/throw/scripts/vector-authoring.mjs)和[重建入口](../apps/throw/scripts/build-vector-art.mjs)：原创路径、统一材质和色板；未用AI图像描摹、未嵌入位图。角色以头、身体、前后手臂、前后腿、围巾等部件形成同一角色的8步行＋8待机姿势，图集使用现行播放机制。**这不是已接入Spine的运行时骨骼动画。**

## 技术事实与观察

SVG可直接作为图片进入Canvas的 `drawImage`，但作为图片时有脚本、外部资源等限制；本轮母版只使用本地几何与渐变，不依赖这些能力。[MDN：SVG作为图片](https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/SVG_as_an_image)。

本轮运行时继续使用固定分辨率的Canvas／WebGL光照。因此，直接显示的SVG近景可以随页面放大保持轮廓清晰，**已经绘入固定画布的整间房间仍受画布分辨率限制**。源格式与最终渲染分辨率不可混为一谈。

文件测量：8道具图集约14.7KB，16姿势主角图集约56KB；原版各图集约1.0MB。此处只比较原始文件，原道具图集另含8件装饰，造型细节也不相同；不能由此推导同等品质下的固定压缩比、量产工时或FPS改善。混合试演仍会加载旧装饰图集。

首次试验采用过大SVG固有尺寸，主角若按完整RGBA缓冲估算约28.1MiB。随后调整至实际试演所需的1600×512图集，RGBA容量估算约3.125MiB；8道具800×512约1.563MiB。该算式是宽×高×4，不是浏览器实际总显存测量。文件较小不免除解码、路径处理、画布及光照成本。

助手当前判断：SVG道具已经可以控制清楚轮廓、材质层和整套配色；角色身份更稳定，但轮廓、衣服体积与动作审美仍需要美术打磨。手工改画减少了现版的柔软细节，不应把更锐利直接等同更漂亮。

## 建议的量产分工

| 资产 | 建议母版 | 量产方式 | 运行时 |
| --- | --- | --- | --- |
| UI、花色、纸牌、状态图标 | SVG＋排版样式 | 共享纸边、描边、色板；数字和文字独立渲染 | DOM／CSS／SVG，本项目这部分已大量采用可缩放绘制 |
| 门窗、家具、普通道具 | 分层SVG | 木作、金属、布料、玻璃组件库；受控尺寸／配色／配件变体 | 少量可直接SVG；大量实例预烘焙到图集 |
| 成人角色、衣装 | 定稿立绘＋分部件矢量或位图 | 统一身材、关节与脚底；复用待机／走路／甩牌／受击动作，角色通过换装和轮廓区别 | 骨骼动画数据＋纹理图集，或烘焙帧；不逐帧重新生成身份 |
| 有机纹理、复杂装饰、特殊插画 | 高质量位图 | AI提供候选，人工选稿、修形、统一色板和尺度 | 带透明通道图集，与其他物件共同受光 |
| 场景 | 模块化建筑＋资产摆放数据 | 房屋构件、家具与灯光按配置组装；少量独特地标打破重复 | 现有分层画布与实时灯光 |

Spine等专用工具提供骨骼数据和纹理图集导出／运行时加载，可作为角色动画后续候选；本轮没有购买、安装或接入，商业授权、运行时版本和项目适配应在选型时另行核对。[官方运行时说明](https://esotericsoftware.com/spine-using-runtimes)。

建议流程：先批准10个代表资产与1名完整动作角色 → 建立色板、成人尺度、形状／材质和阴影规范 → 建组件、分层与关节母版 → 批量产生有限变体 → 检查轮廓、缩小辨识度、关节与脚底 → 烘焙／打包 → 场景共同受光与真实交互验收。AI主要辅助初稿与创意探索；本轮推荐的核心收益来自部件与动作复用。没有实测批量工时，不能承诺一个晚上完成上百个成品。
