## 2. 属性、能力与效果

- **卡牌**：稳定实例，占1／2／3格；分别称小型／中型／大型。不跨路，没有自身生命条；不能对卡牌造成生命伤害，但可以冻结、减速或修改攻击力。
- **核心**：一方共享生命主体，对应旧文档的宿主。每方只有一个，不能因有三路就选出三个同一核心。
- **护幕／屏障**：每方每路独立。普通状态为`intact`（未破）或`broken`（已破）；特殊效果增加`pending_break`（待破）。未破不等于满血。
- **攻击力ATK**：通用输出基准，不自动造成伤害。纯辅助牌也可拥有ATK，供治疗或修屏等系数使用；不依赖ATK的纯功能牌可为0。
- **能力**：一次触发规则和一组效果。**效果**是其中一项实际操作，不把两个名称混为同一级。
- **周期发动**：公共冷却到期的一次发动。多个周期能力共用一次公共发动，不各算一次。
- **响应发动／连锁发动**：由事件或显式连锁产生，分别记录类型，不冒充周期发动。

一条能力的句法为：**“当指定对象发生某事，并满足这些条件时，选择这些目标，执行这些效果。”** 数据统一进入`when`；不再把条件作为另一套平行的触发机制。

## 3. 攻击力与数值计算

### 3.1 输出公式

建议：`当前ATK = round2(clamp((基础ATK + 固定强化合计 - 固定削弱合计) × max(0, 1 + 百分比强化合计 - 百分比削弱合计), 0, ATK上限))`。

比例以整数基点保存，10000=100%。先加减固定值，再对百分比加总后乘一次；同类百分比不是彼此连乘。强化／削弱有独立来源、持续时长和到期记录。基础ATK不被永久改写。

例如基础ATK40，固定+10、百分比+20%、百分比-10%，当前ATK为55。造成100%ATK物理伤害的请求量为55；实际扣血还要经过护幕、减免等结算。

输出量支持：固定值、当前来源卡ATK×系数、当前事件实际生效量×系数。比例结果可有显式上限；不允许自由代码或任意对象路径。ATK系数可超过100%，上限由约束配置决定，不能沿用旧稿“所有比例最多100%”。

ATK在本次能力提交时快照，已发出的弹道及已经施加的持续伤害强度不随后来强化／削弱重算；新一轮能力读取新的ATK。每个效果都承担预算，多个100%ATK效果不会因为共用同一属性而免费。

### 3.2 “25%攻击力的灼烧”如何解释

**本稿建议，需重点确认**：25%ATK换算为本次施加的“灼烧强度”，不是一次即刻伤害，也不是整段持续时间的总伤害。卡面必须写“施加相当于25%攻击力的灼烧强度”，避免误导。

例如ATK40，施加10点灼烧强度；每0.5秒按当前强度伤害，然后强度减少1，最终降到0。孤立施加、无其他变化时总请求伤害为10+9+…+1=55。若希望表达“总共只造成10点灼烧伤害”，需要另一种固定总量持续伤害模块，不可使用同一词条偷换语义。

侵蚀也用施加强度表达：每1秒按强度伤害并按规则削护幕上限，强度不自行衰减。它与终局的“腐化”是不同效果。

为容纳ATK百分比，建议强度支持0.01精度；原整数层数可作为整数强度导入。灼烧全路上限24、侵蚀上限12先保留为**待校准的继承值**，不是已证明适合新ATK体系的最终上限。每次记录请求量、实际添加量和封顶损失。

持续状态保留贡献来源及其因果链。一次路线跳伤只有一个受伤事件；“某卡造成伤害”按该次真实损失中各来源的强度占比分摊归因，不把总伤害重复记给每张卡。定点余数按稳定来源顺序分配；零贡献不产生造成伤害事件。衰减也按贡献比例扣减并稳定分配余数。

## 4. 触发词库：统一“……时”

下表覆盖当前对象模型中主要可行事件。它们是**规范候选**；只有对应事件被引擎实现并认证后才可执行。表中保留项只用于创意登记。

### 4.1 时间与发动

| 玩家表述 | 事件ID | 触发含义 |
| --- | --- | --- |
| 战斗开始时 | `battle_started` | 初始化完成后一次 |
| 战斗进行到X秒时 | `time_reached` | 指定战斗时间首次到达一次 |
| 每经过X秒时 | `interval_elapsed` | 独立世界时间间隔；不受加速影响，不能伪装成普通冷却 |
| 本牌冷却完成时 | `cooldown_ready` | 默认周期触发；省略触发说明的生成意图在定稿时必须补成此事件 |
| 本牌／相邻牌／某路牌／任意牌发动时 | `card_activated` | 通过选择器指定主体；过滤周期、响应、连锁三种发动类型 |
| 本牌收到连锁触发时 | `chain_received` | 已接受一次合法连锁请求时，不能仅因尝试失败触发 |
| 本牌／指定卡牌获得充能时 | `cooldown_advanced` | 实际增加进度>0；记录请求和实际增加量 |

周期冷却从0进度开始，无免费首发；纯被动公共冷却为`null`。一次周期到期即消费冷却，即使所有条件不满足仍算一次周期发动。响应能力则须满足条件并成功提交至少一个有合法目标的效果，才计为响应发动。结果为0不撤销已经提交的发动。

### 4.2 伤害、恢复与护幕

| 玩家表述 | 事件ID | 必须区分 |
| --- | --- | --- |
| 本牌／指定卡牌造成伤害时 | `damage_dealt` | 物理／灼烧／侵蚀；实际伤害>0；核心与护幕损失分开 |
| 己／敌／双方护幕或核心受到伤害时 | `damage_received` | 指定受伤主体与伤害类型；腐化可显式订阅 |
| 造成物理／灼烧／侵蚀伤害时 | `damage_dealt`＋类型过滤 | 不是三个含糊的重复事件 |
| 造成致破幕伤害时 | `barrier_broken`＋破幕来源过滤 | 待破期间不算破幕；延迟破幕保留原始零血来源 |
| 本牌／指定卡牌产生有效治疗时 | `healing_done` | 按实际恢复量，过量治疗不算 |
| 己／敌核心实际被治疗时 | `healing_received` | 指定接收核心；同一效果只产生一次接收事件 |
| 本牌／指定卡牌产生有效修屏时 | `repair_done` | 实际恢复护幕生命>0 |
| 己／敌／双方指定护幕实际被修复时 | `barrier_repaired` | 不能把满护幕的0修复作为成功 |
| 指定护幕生命首次降到0时 | `barrier_zero` | 从正数到0的边沿；0血继续受击不重复触发 |
| 指定护幕真正破裂时 | `barrier_broken` | 状态转为broken；与零血事件分开 |
| 指定护幕进入／结束待破状态时 | `barrier_grace_started` / `barrier_grace_ended` | 结束要标明被修复取消或到期破裂 |

### 4.3 状态、属性与全局

| 玩家表述 | 事件ID | 边界 |
| --- | --- | --- |
| 指定对象被施加灼烧／侵蚀／加速／减速／冻结时 | `status_applied` | 实际新增强度或延长时长>0；刷新无变化不触发 |
| 指定状态被移除时 | `status_removed` | 被清除或替换，记录原因；相应移除效果未实现时不能凭空订阅来源 |
| 指定状态自然结束时 | `status_expired` | 与主动移除分开，结束通知一次 |
| 指定卡牌攻击力提高／降低时 | `attack_changed` | 有效ATK变化，过滤变化方向；上限导致无变化不触发 |
| 指定对象生命比例／ATK／状态强度跨过阈值时 | `stat_crossed` | 由阈值一侧进入另一侧才触发，不是条件持续成立就每帧触发 |
| 腐化开始时 | `corruption_started` | 全局阶段转换一次 |
| 每轮腐化生效时 | `corruption_pulse` | 每轮一个全局事件，不按六条护幕重复发六次 |
| 战斗结束时 | `battle_ended` | 只用于日志、展示、结算通知；不能新增战内伤害或自行发奖励 |

**保留目录**：弹药耗尽／装填时、储能达到阈值／被消耗时、变形时、增幅器被拆解／复机时、进入／离开场上时。须先定义相关资源或生命周期模块；v0没有卡牌生命，所以“卡牌死亡时”当前不成立。

### 4.4 条件合并到触发语句

例：“**相邻小型己方卡牌周期发动时，若本路护幕低于50%，且本能力间隔已结束，则修复本路护幕。**”它是一条`when`：事件、主体范围、事件过滤、状态条件、计数条件。

可用状态条件包括：目标存在、尺寸、是否有公共冷却、护幕状态、生命／护幕比例、ATK值、灼烧／侵蚀强度、是否处于某状态、是否本路独占、实际事件量阈值。比较支持小于／不大于／等于／不小于／大于；多个条件先按全部满足处理。每第N次合格事件可触发，计数按能力实例隔离；间隔内的合格事件仍计数，错过的第N次不补发。

条件和目标在接受触发时快照。需要“命中时判断”时，使用伤害／命中结果事件后续能力，不能把发动时条件默认为命中时条件。无伤害的接触命中若需要独立机制，另登记模块。

## 5. 目标词库：对象、阵营、范围、筛选、数量

### 5.1 己方和敌方卡牌

以下范围对己方、敌方都可使用，也可选双方后合并去重：

| 范围／筛选 | 定义 |
| --- | --- |
| 自身／事件发起牌／事件目标牌 | 读取明确实例；事件没有对应卡牌时为空 |
| 相邻卡牌、相邻左侧、相邻右侧 | 己方按同路卡牌真实边缘相接；敌方按来源卡占格投影到敌方本路后判左右相邻，卡面注明“敌方投影相邻” |
| 同路卡牌、左路／中路／右路卡牌 | 路线使用统一世界坐标，不因上下方显示而交换左右 |
| 相邻路线卡牌 | 来源在边路时1路，在中路时2路 |
| 对位卡牌 | 敌方同路占格与来源投影重叠的卡牌；同一大卡只选一次 |
| 全部卡牌 | 所选阵营所有在场卡牌 |
| 小／中／大型卡牌 | 按1／2／3格筛选，可与任意范围组合 |
| 有冷却／被动卡、冻结／加速等状态卡 | 使用实际状态和已编译能力筛选，不看名字／描述 |
| 最高／最低攻击力、最接近发动的卡牌 | 明确指标排序，同值按路线、起始格、稳定UID |
| 随机X张、任意X张、全部符合条件的牌 | “任意”须具体选择算法；随机无放回，不足X张则选全部有效候选 |

是否排除来源卡必须显式填写。敌方卡牌可被强化、削弱、加速、减速或连锁，是否合理由预算与设计审核判断，不因阵营直接禁止创意。

### 5.2 己方、敌方、双方护幕

支持：本路、相邻路线、指定左／中／右路、全部护幕、随机X面护幕，以及最低／最高剩余比例的护幕；可筛选未破、待破、已破、受灼烧／侵蚀的路线。

护幕的直接伤害只作用于护幕，不溢出到核心。需要“先护幕，溢出打核心”应选择**路线**目标。修屏只接受护幕；已破修复为0，待破是否可修复见特殊模块。

灼烧、侵蚀绑定路线；将其作用于核心的独立状态需要新模块，不能通过换目标字符串自动获得穿幕持续伤害。

### 5.3 己方、敌方、双方核心与路线

核心支持己方、敌方、双方、随机一个以及按剩余生命比例选择；每个核心只出现一次。直接选择核心造成物理伤害属于**穿幕攻击**，须显示并单独计入预算，不能伪装成普通路线攻击。

路线支持己／敌／双方的本路、指定路、相邻路、全部或随机X路。路线伤害默认先护幕、溢出到核心；护幕已破则全额打核心。相同核心由不同路线分别受到伤害是多个明确攻击包，不是多选去重错误。

### 5.4 多目标与随机

每个多目标效果必须写“每个目标各获得X”或“所有目标共分X”。总量分摊等分到0.01，余数按稳定目标顺序分配；不得复制整份预算给每个目标。

随机必须由对局种子、事件ID、效果ID与抽样序号派生，候选先稳定排序，无放回取样。保存算法版本、计数和最终目标ID。禁止使用墙钟、UI帧率或未固定的随机源。无候选时不抽样、不自动换阵营；已锁定目标失效时记为无效，不重新抽奖。

触发中的“随机X张牌发动时”建议在战初固定观察集合；事件过滤不每次重抽。效果目标的随机则每次提交重新抽取，两者在数据中分别标明。

## 6. 基础效果词库

| 标识 | 玩家含义 | 参数与规则 |
| --- | --- | --- |
| `physical_damage` | 造成物理伤害 | `magnitude`；路线／护幕／核心目标采用上节各自路由；沿用认证的物理减免 |
| `apply_burn` | 施加灼烧 | `magnitude`转换为路线强度，0.5秒跳伤并衰减；不再只接受固定整数层数 |
| `apply_corrosion` | 施加侵蚀 | `magnitude`转换为路线强度，1秒跳伤并削护幕上限，强度不自然衰减 |
| `repair_barrier` | 修复护幕 | `magnitude`；最多填到当前上限，不恢复被侵蚀削掉的上限 |
| `heal_core` | 治疗核心 | `magnitude`；最多填满，胜负确定后不能复活 |
| `haste` | 加速 | `rateBps`和`durationMs`；增加冷却推进速率，不改飞行速度、不改基础冷却 |
| `advance_cooldown` | 充能 | `amountMs`；增加冷却进度，纯被动无效；建议截断到下一次发动所需进度 |
| `trigger_chain` | 连锁触发 | 立即请求目标牌公开的连锁入口能力；不消费／重置其公共冷却，不执行任意脚本 |
| `slow` | 减速 | `rateBps`和`durationMs`；降低冷却推进速率 |
| `freeze` | 冻结 | `durationMs`；暂停周期冷却和发动，充能无效；不取消已飞出的攻击 |
| `modify_attack` | 强化／削弱攻击力 | `mode: flat/percent`、有符号`delta`、`durationMs`；按第3节的统一公式 |

### 状态规则建议

- 加速取当前最强正加速，减速取当前最强减速，不累乘；`推进倍率=clamp(1+加速率-减速率,0,2.5)`。100%加速与50%减速同时存在为1.5倍，这是**新建议**，不冒称等同旧牌规则。
- 冻结优先于加减速；建议冻结也暂停该卡的事件响应和连锁入口。已投射攻击及路线持续状态继续生效，卡牌作为被选择目标仍可被修屏以外的合法效果影响。
- 同来源同效果的状态刷新剩余时长，不叠加一份新强度；不同来源的攻击力修正按公式相加。加减速同来源取原值与新值中较强者、到期时间取较晚者；旧修订不能在同一场静默改变参数。
- 建议初始时长上限：加减速4000毫秒、冻结2000毫秒、攻击力修正10000毫秒；均为待校准参数，认证模块可使用不同公开配置。
- 到期状态先移除，再读取同一时刻的新触发快照。属性变化只在真实有效值变化时发事件。

所有数值需经过预算。给全场加速的强度不能用单目标加速的价格；攻击力强化同时放大伤害、灼烧、治疗等所有引用ATK的效果，必须计入组合风险。

## 7. 连锁触发：允许组合，限制回路

draft-0.1的“子效果不能触发其他被动”在本版取消，改为**有因果记录的有限连锁**：

1. 每条事件保存`eventId/rootEventId/parentEventId/depth/visitedAbilities`，旧牌适配也必须传递，不能重置后规避限制。
2. 同一根事件中，同一实例的同一能力最多执行一次；A→B→A第二次A被规则抑制，正常结束该分支并记录原因。其他根事件仍可再次触发。
3. 建议深度最多8、每根最多64次能力提交；这些是明确可见的玩法连锁边界，达到边界的分支不再提交。工程事件总量溢出则是实验错误，不能判成正常战斗结果。
4. 事件响应与连锁共用能力的间隔／每战次数，不得通过显式连锁绕过。普通能力最小响应间隔建议10毫秒；具体强度仍由预算控制。
5. 每张可接受显式连锁的卡指定一个`chainEntryAbilityId`。该入口不能依赖不存在的原事件伤害字段，执行时重新选自己的目标、读取自己的ATK，并记录发动类型`chain`。
6. 连锁跳过入口的事件名称匹配，但仍检查其状态条件、冻结、次数及资源前提；公共冷却不重置。触发自己与无公开入口的目标无效。
7. 充能导致同一时刻立即到期的周期发动继承原根事件，不创建新根洗掉路径；自然时间推进到新的周期事件才可建立新根。

伤害跳伤可以触发明确订阅的响应。合并持续伤害来源的响应继承贡献来源的因果路径并合并已访问集合，不能通过合并状态抹去回路记录。每根事件的预算计数须保留到其延迟子事件全部结束。

## 8. 特殊效果：专门模块，不要求硬塞进基础词条

特殊能力可以改变普通结算边界，但必须登记`specialId`、精确版本、参数、适用目标、执行钩子、状态、相互作用与验收用例。AI可提出尚未实现的特殊创意；只有受信任的规则模块通过认证后，才能出现在可执行蓝图中。模块不是AI提交的脚本，也不是泛化“自定义文字”开关。

### 示例：`barrier_break_grace/1-draft`

**用户方向**：护幕生命为0时，延缓破损5秒。**本稿补充解释，待确认**：

- 在正血降到0、普通破幕提交之前，用专门`before_barrier_break`钩子进入`pending_break`，截止时间=当前时间+5000毫秒。
- 待破期间保持护幕身份与尚未被拆解的增幅器；与生命比例相关的增幅条件仍按0血判断，不保证所有增幅器都有收益。
- 0血护幕没有可吸收生命；后续路线伤害打核心。原致零一击的溢出也打核心。**延缓破损不等于5秒无敌。** 护幕专属伤害则只能造成0护幕损失。
- 待破期间可以修屏。修复到正数立即取消待破并回到未破状态，但本次特殊保护已消费；再次归零不自动再延缓。
- 到期仍为0才真正破裂，禁用该路增幅器并发`barrier_broken`。同一时刻到期先于普通修复，不能靠同毫秒修复抢救。
- 建议每面护幕每战仅一次，多个来源共享此次数，不能互相刷新5秒。多个合格来源按更长时长、再按稳定ID选择一次。
- 作用于目标护幕的模块在战初登记为一个保护资格；每张源卡最多登记一面。源卡后来被冻结不撤销已经登记的资格。若要动态赋予／解除资格，需另一模块版本。

普通`barrier_zero`事件发生在这一钩子决定之后，不能用普通事后触发偷改已经发生的破裂。该模块还须专项验证与侵蚀削上限、腐化、修屏、拆解／复机和多来源的相互作用。

## 9. 时间与流畅度

当前代码的0.25秒步长与90秒上限是旧实现事实。**新实验配置建议用整数毫秒，固定逻辑步长10毫秒（100Hz）**；以目标设备性能测试决定是否接受，不能承诺任意设备都支持更小步长。

冷却进度保存为定点“基础冷却毫秒”，每10毫秒按冻结的倍率增加；允许小数进度，避免低倍率被整除成0。到期时间落在逻辑网格，时间值必须为10毫秒的整数倍。普通弹道先保留1250毫秒，不因步长变细变成50毫秒。

界面用相邻确定性状态和经过时间做逐帧插值，按60Hz／设备刷新率绘制平滑进度条。插值不触发技能、不改状态、不用真实帧间隔直接结算伤害。暂停／回看／冻结时从对应快照插值，后台补帧也执行同样的逻辑步。

同一时刻建议顺序：状态／待破到期 → 到期普通伤害与持续伤害／腐化批次 → 实际损失与破幕处理 → 响应批次（按深度与稳定队列） → 普通支援效果／冷却推进与新发动 → 同时胜负检查。未发出的周期攻击不允许已致死核心在本批后补发；同批已经承诺的攻击仍结算。更精确的调度顺序随引擎版本冻结，不能直接替换旧回放调度器。

## 10. 全局腐化：90秒后的终局压力

这是**战斗规则配置**，不是让AI自由附加到某张卡上的效果。名称`corruption`，与路线状态`corrosion`（侵蚀）分开。

用户明确：对局超过90秒后持续扣血，优先屏障，没有屏障则核心，伤害逐秒递增。

**本稿建议的可执行解释，待确认**：

| 项目 | 建议 |
| --- | --- |
| 启动／首次伤害 | 90000毫秒进入腐化，91000毫秒第一轮，之后每1000毫秒一轮 |
| 第n轮每路伤害 | `1 + (n-1) × 1`点，即1、2、3……；起始值与增量待平衡 |
| 作用范围 | 双方各三路同时收到一个路线伤害包，共六包 |
| 路由 | 每路先扣自己的护幕，溢出打己方核心；该路已破或待破且0血时全额打核心 |
| 全部破幕时 | 每方核心每轮承受三路合计3n点；不是只受n点，界面须说明 |
| 伤害性质 | 环境伤害，无卡牌ATK、不触发物理专属减免或汲取，不削护幕上限 |
| 触发互动 | 可被明确订阅`corruption`的受伤事件观察；不能算作某张卡“造成伤害” |
| 特殊保护 | 可触发未消费的延缓破损资格，但0血后仍打核心，不被待破状态无限挡住 |

双方同轮致死判平。90秒不再自动结束；仍存活则继续腐化。为防失控模拟，另设暂定300000毫秒工程预算；触顶报告`SIMULATION_BUDGET_EXCEEDED`，不宣称正常平局或平衡已通过。递增伤害不等于数学保证任何恢复构筑都会在预算内结束。

## 11. 样例与需要确认的细节

以下数值仅展示结构，不改变既有同名卡：

- **留温杯**：1格、ATK8、6秒周期；治疗己方核心100%ATK，发动时本路护幕未破或待破，则修复75%ATK。
- **火星盒**：1格、ATK40、6秒周期；对敌方本路造成100%ATK物理伤害，并施加25%ATK灼烧强度。两项分别预算，不能把后者当成总计10伤害。
- **伴行小铃**：1格、ATK0、纯响应；相邻己方牌周期发动时，从己方左路有冷却的牌中确定性随机选2张，每张充能0.5秒，间隔3秒，每战最多30次。
- **余光护罩**：1格、ATK0、特殊被动；登记本路护幕一次5秒延缓破损资格，0血期间仍会溢出伤核心。

本版已补齐原稿的五处待调整批注。需要你重点审阅的建议是：**灼烧百分比按强度解释、ATK加减顺序、10毫秒步长与插值、有限连锁规则、零血护幕不免伤且可修复、腐化按三路分别扣血及起始增量**。
