# 03 · 卡牌、道具与变种

2026-10-12 当前规则：对决 v16 / 冒险 v10。第四幕、26件本体字段改装、金级同款材料且不限数量、自动出牌、三人独立配置见[ADR-0064](../design-log/decisions/ADR-0064-throw-millbrook-upgrades-and-autoplay.md)、[第四幕内容](../F9_THROW_MILLBROOK_2026-10-12.md)与[实测记录](../design-log/iterations/F9/2026-10-12-throw-millbrook-upgrades-and-autoplay.md)。下文此前版本的机制及证据有冲突时按本修订为准；历史结果不重写。


## 1. 内容的三种「卡」

| 类别 | 存在哪 | 玩家怎么用 | 规模 |
|---|---|---|---|
| **道具** item | `throw-loadout.ts` `ITEMS` | 放进 10 格巡演箱，出牌时按条件触发；相邻可增幅 | 1–3 格 |
| **遗物** relic | `throw-loadout.ts` `RELICS` | 每人最多一件，改一条全局规则；也可不带 | — |
| **变种** enchant | `throw-enchant.ts` | 装在某张扑克牌的牌位上，这张牌被甩出时生效 | 没有张数上限（ADR-0058），约束来自收集：每个变种只有一份，并且固定在某张牌上 |

另有**预设卡组**（`PRESETS`）：道具 + 遗物 + 克制声明 `beats` 的组合，供 AI 和练习场使用。

**角色身份**（[ADR-0057](../design-log/decisions/ADR-0057-throw-troupe-gauntlet-identity.md)，`throw-performer.ts`）：每人一条天赋、一个手法（主动，有冷却）、一副专属牌匣；v11 起气场可以因台龄等成长不同。v12 伊莱手法由假洗改为快抽，最多补 5 张、15 秒冷却（[ADR-0060](../design-log/decisions/ADR-0060-throw-quick-draw-and-readable-progress.md)）。新增角色时：

- 天赋必须改写一条现有机制，不能是伤害倍率；
- 手法必须原子化，失败时原样返回，进入事件流，并在 `aiWantsSleight` 里写出 AI 什么时候用；
- 专属牌匣要通过 `validDeckBook`；
- 在 `story-sim.mjs` 里看他作为对手时的难度。

**v9 两条构筑规则**（[ADR-0056](../design-log/decisions/ADR-0056-throw-v9-build-space.md)）：①**凑满 3 件**：护盾、治疗道具在巡演箱里同家族不足 3 件时，产出的护盾、治疗、吸血减半（`SPLASH_MIN_ITEMS`）。规则文字要写在受影响道具的 `text` 里。②**戏服**：亮片马甲（只有 1 个家族时 +25%）、定制燕尾服（恰好 2 个家族时各 +15%），辅助道具不算家族。新增护盾或治疗道具时，要想清楚它在「凑 3 件」里的位置；新增攻击家族时，先用 `build-audit.mjs` 看它会不会成为新的万金油。

v6 新建冒险的初始箱子使用单张道具「飞牌修缮箱」与「穿幕细针」，不带遗物。第一课奖励换调风铃／清露药包（第二场是火系，礼物要能解火），米娅奖励守灯小毯／折光铜镜，先教单张、轮换花色和单张黑桃防守；资格赛首胜后才开放双响茶壶、补丁旧伞、抖擞披风等道具。v3 旧存档迁移保留此前已解锁的历史道具。三息理线盒（旧 id `order`）从遗物池移除，整理是所有人的默认机制，冷却 20 秒。新增道具不要再次把默认整理包装成需要装备的能力。

当前顺子／同花从 3 张起成立；以最少 3 张触发的道具要写清短组合与 5 张组合的收益差别，避免降低触发门槛后无条件沿用原 5 张的全部收益。战斗策略提示应从实际装备的触发条件提取，包含单张／对子／组合／指定花色等方向，不能只依据预设名字。

## 2. 设计语言：花色锁定状态

这是整个卡池的第一原则，所有新内容都要遵守：

| 花色 | 状态 | 家族 `family` | 图标底色 |
|---|---|---|---|
| ♠ 黑桃 | 护盾 | `shield` | `#4f7fae` |
| ♥ 红心 | 治疗 | `heal` | `#c98f7c` |
| ♣ 梅花 | 剧毒 | `poison` | `#6d9647` |
| ♦ 方块 | 灼烧 | `burn` | `#d0772f` |
| — | 直伤 | `damage` | `#b3263a` |
| — | 辅助（抽牌、增幅、净化） | `utility` | `#4fa39a` |

**为什么**：对手亮出的花色直接暴露他的意图，玩家「这手出几张哪种花色」就是战术决定。一件「每张 ♣ 加护盾」的道具会破坏这种可读性——不要做。

## 3. 克制环

v4 起，克制靠**机制**而不是数值。新内容要清楚自己站在环上的哪个位置。

| 克制 | 机制名 | 规则 |
|---|---|---|
| 治疗 → 剧毒 | 净化 | 每次治疗净化「名义治疗量一半」的剧毒，满血也生效 |
| 剧毒 → 护盾 | 绕盾 + 毒发 | 剧毒无视护盾；受害者每攒 5 张手牌，毒伤 +1 |
| 护盾 → 灼烧 | 闷火 | 有盾时新灼烧减半，灼烧只烧盾不伤血，并多退 2 层 |
| 灼烧 → 治疗 | 焦灼 | 着火时治疗只剩六成；v13 已移除出牌自伤，灼烧只按秒结算 |
| 快甩 → 护盾 | 单张削盾 | 单张被盾挡下多耗 10%；铜镜不反弹单张 |
| 快甩 → 剧毒 | 抖擞 | 抖擞披风每次出手净化 3 层毒 |
| 蓄爆 → 续航 | 压轴重创 | 顺子及以上命中，目标 5 秒内治疗六成 |
| 蓄爆 → 快甩 | 扇面格挡 | 手牌 ≥7 张时单张直伤减半 |
| 护盾 → 蓄爆 | 反击门槛 | 回声针盒只在被 ≥3 张命中时反击 |
| 存活 → 所有人 | 落幕 | v14 起 60 秒起双方每 0.5 秒受递增伤害，单次值按整秒递增；基础补牌每 1.5 秒一次 |

六套预设和它们声明的克制（`beats`）：

| 预设 | 克制 |
|---|---|
| 快甩 quick | 护灯、青苔 |
| 护灯 guard | 余烬、星光 |
| 余烬 burn | 回甘（v13 不再沿用烫手反快甩的宣称） |
| 回甘 mend | 青苔 |
| 青苔 poison | 护灯、星光 |
| 星光 combo | 回甘、快甩 |

详细推导见 `docs/F9_THROW_DECK_BALANCE_V4_2026-10-09.md`。

## 4. 设计一件新道具

### 4.1 数据格式

```ts
{
  id: 'stride',              // 稳定 id，小写英文，发布后不改
  name: '抖擞披风',           // 物件名：一件旧剧团里能找到的东西
  tag: '解毒',                // 兼容旧内容字段；当前双标签统一取 throw-kit-guide.ts
  size: 1,                   // 1–3 格
  family: 'utility',         // 决定图标底色和「护盾类」等分类
  text: '每次出手：净化自身 3 层剧毒。',      // 规则原文，逐字对应代码
  quip: '一直动来动去，毒都追不上。母亲说这叫“坐不住”。', // 俏皮话，见文案指南
}
```

### 4.2 文字规范

- 句式：**「触发条件：效果 数值。」**。例：`对子、两对或葫芦：护盾 +30。`、`每张♠：护盾 +14。`
- 术语只用这些：直伤、护盾、治疗、灼烧、剧毒、净化、迟缓、穿透、抽、力量、反击。新术语要先在规则弹窗里定义。
- 数值写死在文字里，不写「少量」「大幅」。
- 物件名是「旧剧团的旧东西」：伞、毯子、茶壶、闹钟、放映机、风扇。不要写「XX 之剑」「XX 护符」。
- 俏皮话遵守 `docs/F9_THROW_VOICE_GUIDE_2026-10-09.md`：英式冷幽默、轻描淡写、自嘲，不玩梗、不用网络流行语。

### 4.3 数值参考点

没有公式，但有一组已经过矩阵验证的锚点。新道具先和同尺寸、同家族的锚点比：

| 尺寸 | 锚点 | 说明 |
|---|---|---|
| 1 格 | 飞牌修缮箱：单张 +8 直伤 | v6 补牌／短组合调整后的高频基线 |
| 1 格 | 抖擞披风：每次出手净化 3 毒 | 纯反制，没有输出 |
| 1 格 | 浸露线盒 / 鼓火风扇：相邻 +50% | 增幅件，本身不产出 |
| 2 格 | 双响茶壶：对子类 +10 直伤 | 通用填充 |
| 2 格 | 补丁旧伞：对子类 +30 护盾 | 护盾数值 ≈ 直伤 ×3 |
| 2 格 | 守灯小毯 / 回暖小灯 / 青苔药匣 / 余烬小炉：每张对应花色 +14 盾 / 9 疗 / 3 毒 / 3 火 | 四个花色的「主引擎」，互为参照 |
| 3 格 | 织序风扇：3／4／5 张顺子 +21／28／36，附带扇面格挡 | 组合越长收益越高 + 防守附加 |
| 3 格 | 护心放映机：附加当前护盾 40% 直伤 | v6 盾流的输出出口 |

经验法则：

- 条件越难满足，数值越大；但单件道具不能单独扭转一个克制关系。
- 持续状态（毒、火）每层价值远高于一次性直伤——毒每层都会每秒跳，所以基数要低。
- 无上限的成长（力量、叠层）必须封顶（`MAX_POWER = 30`）。
- **不要做「位置谜题」**（v4 删掉了「最左/最右格额外效果」）；相邻增幅是唯一的位置规则。

### 4.4 落地步骤

1. `ITEMS` 里加条目（4.1）。
2. `throw-duel.ts` 的 `itemEffects` 加一个 `case`，返回 `{ name, kind, value }` 列表。它同时服务预览和实际出牌。
3. 需要新的效果种类（`kind`）？在结算处加处理，并写机制测试。
4. `src/app/stage/glyphs.tsx` 的 `icons` 里画图标（见 04 第 5 节）。**没有图标测试会失败。**
5. 决定获取途径：起始箱、剧情奖励（`Reward.items`）、商店（`SHOP`）。
6. 如果是某个预设的一部分，更新 `PRESETS`，跑矩阵。
7. 单项测试 + 矩阵 + 剧情模拟（见 08）。

### 4.5 当前展示与布阵交互

- `throw-kit-guide.ts` 的 `ITEM_LABELS` / `RELIC_LABELS` 为每件道具和遗物定义且只定义两个标签：`play`（打法/触发）与 `effect`（主要效果）。新内容必须补齐，不能只填写旧 `tag`。小票和菱形底板只是装饰，不承载额外规则。
- `kitCompatibility` 从明确的机制关系返回解释：共同触发、状态供给、有效相邻增幅等。同色或同家族本身不构成推荐；双邻罗盘与戏服还要满足其真实前提。
- v14 暂停展示可搭配角标和配套高亮，保留机制函数。当前筛选为打法/效果两行，类内和类间均可多选，所有条件取交集；`kitFilterTags` 包含真实次要效果，不能只凭卡面主标签筛选。商店道具与遗物共用同一筛选函数。
- v15 候选由 `availableKitFilterTags` 读取当前结果，每个可见新标签都至少有一个共存物件；选中标签可以撤销。切换商品/收藏分类清空条件，不能带入不相容筛选。布阵背包、背包收藏页、商店共用该逻辑。
- 双人备战分首发/第二棒编辑，每人独立箱、遗物、牌匣；`freeTeamPool` 排除另一人的已配物件，`validTeamAllocation` 在启动前再次验证无重复和真实拥有。白牌不限，具体非白牌变种按完整牌位引用独占，不能只按附魔名称去重。想移交物件，先从原队员取下。
- 对手推荐大拇指位于物件图标左上角，只读已公开教程或已揭示情报。第三章开始后旧城也不再显示新手建议；没有可见信息就不推荐，不能窥读隐藏构筑。
- 背包首件默认选中；详情区固定高 140 px，正文内部滚动，窄屏仍保留操作栏。
- `swapThrowItems` 先验证完整候选布局，成功才替换。场内互换各自起点，背包↔场上一换一；不同尺寸需要两边都放得下，不能挤动第三件或越界。背包内只调整展示顺序。
- 以 `throw-kit-guide.test.mjs` 检查分类覆盖、真实机制推荐与失败原子性。点击、拖拽和窄屏都需实际浏览器验收。

## 5. 设计一件新遗物

遗物改的是**规则**而不是数值：手牌上限、状态加成、反射。遗物通常是预设的规则核心；不需要专用全局规则的构筑可以不带遗物（v6 星光组合不带遗物）。新遗物需要回答：「它让哪种打法第一次成立？」如果答案是「让某个已有打法更强」，那它应该是道具。阶段补牌与默认整理属于公共机制，不能重新包装成遗物专属能力。

v7 起遗物验收用 `relic-swap.mjs`（每格至少 120 局）：专属遗物排本流派前 2；没有遗物是 3 套以上卡组的最佳；每件遗物至少在一套卡组上比不带高 5 个百分点。两条经验：

- **遗物不给抽牌。** 抽牌对所有卡组都有用，带抽牌的遗物会变成万金油（v5、v6 的接力闹钟）。
- **通用触发要和本流派挂钩。** 「受击回血」这类谁都能触发的效果，收益要跟本流派的道具数量挂钩（v7 补缝毯：每件治疗道具 +1）。

步骤同道具，效果代码不在 `itemEffects`，而是在对应的结算点（例：`handLimit(relic)`、反射在护盾吸收处）。

## 6. 设计牌的变种

### 6.1 结构

```ts
// 通用附魔（稀有/史诗），任何牌都能装
{ id: 'edge', rarity: 'rare', name: '磨边', text: '甩出时：直伤 +3。', quip: '…', effect: () => one('磨边', 'damage', 3) }

// 传奇附魔：每张牌一种，按 [花色][点数] 写在 LEGENDS 里，id 自动生成为 L + 花色字母 + 点数（例 LSJ = 黑桃 J）
11: { name: '伞兵杰克', text: '单张甩出：直伤 +8，穿透 30%。', quip: '…', effect: (c) => (single(c) ? [...] : []) },
```

可用字段：

| 字段 | 作用 |
|---|---|
| `points` | 点数倍率（镀金 ×2） |
| `plus` | 点数加值（描银 +4） |
| `wild` | 凑同花时当任意花色 |
| `weight` | 道具按「每张某花色」结算时算几张 |
| `effect(context)` | 甩出时的效果，可读取 `EnchantContext`：生命、护盾、自身/对手状态、手牌数、出手次数、是否落幕、是否在牌型里 |

### 6.2 稀有度规则

| 稀有度 | 定位 | 上限 |
|---|---|---|
| 普通（白牌） | 无附魔 | — |
| 稀有 | 一张牌一份小加成，≈ 1 格道具触发一次 | 无额外稀有度数量上限；按已收集变种 |
| 史诗 | 改规则，或明显的数值（×2、百搭、共鸣、抽牌、穿透） | 同上 |
| 传奇 | 每张牌专属，围绕该花色的状态，覆盖不同时机 | 同上 |

旧 8 / 4 / 3 上限已由 [ADR-0058](../design-log/decisions/ADR-0058-throw-deckcase-uncapped.md) 取消。当前仍是一副 52 个牌位，每牌位装备一个合法变种；收集与独占分配约束保留。

牌匣的「有变种」筛选查实际拥有且对应合法牌位的非白牌变种，包含收集后尚未装备的牌。不能只看当前 `book`，否则未装的新奖励会被筛掉。放大牌匣与牌面只是展示调整，不改变牌位、拥有或装配数据。

传奇的分工（每个花色都照这个骨架写 13 张）：

- **2**：共鸣 ×3，放大本花色道具。
- **3–10**：分别覆盖单张、对子、顺子、同花、落幕、低血、对手状态、第 N 次出手等时机。
- **J**：单张的小技巧。
- **Q**：「夫人 / 女王」，通常读对手状态（对手的火、盾），或平时有底、落幕时爆发。
- **K**：百搭 + 本花色效果。
- **A**：本花色最强的单牌，通常在落幕时更强。

### 6.3 变种的硬规则

- 变种**不受相邻增幅**，防止和联灯接线盒叠成乘法爆炸。
- 变种**不改抽牌顺序**：牌匣只装饰牌，洗牌只看种子。
- 竞技预设和平衡回归测试一律用白牌；变种的强度在剧情里由敌人的牌匣抵消（见 06）。
- 文字和效果在同一行，改一个必须改另一个。
- **落幕只能当加成**（v7）：一张指定的牌在落幕后被甩出的概率只有约 1.3%，所以任何变种都要有随时可用的基础效果。
- **稀有附魔按点数分段**（v7）：2–8 是小牌，效果完整；9 及以上只有象征性的效果。新的稀有附魔也照此设计，让「装在哪张牌上」成为真实的选择。

### 6.4 落地步骤

1. 在 `GENERIC` 或 `LEGENDS` 里加条目。
2. 新的 `kind`（如 `antidote`、`douse`）需要在 `throw-duel.ts` 结算处支持。
3. `throw-enchant.test.mjs` 加测试：触发 / 不触发 / 上限校验。
4. 跑「满牌匣 vs 白牌」对比（08 第 4 节），确认整体优势仍在 +25 个百分点左右，没有单一附魔独大。
5. 决定获取途径：商店（`SHOP` 里 `kind: 'variant'`，`ref` 写作 `'{suit}-{rank}:{id}'`，例 `'0-11:LSJ'`）或剧情奖励。

## 7. 已知的开放问题

**混搭构筑过强**：护盾 + 治疗 + 快甩的混搭对所有预设胜率 74–100%。消融实验显示每一块都有贡献；「催信闹钟」和护盾转伤的「护心放映机」会扭曲预设之间的对比。完整的构筑空间审计尚未做——**新增道具时请顺手用 `balance-matrix.mjs --kits` 测一下最强混搭**，不要让这个问题变得更严重。
