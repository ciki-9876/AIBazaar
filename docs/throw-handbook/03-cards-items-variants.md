# 03 · 卡牌、道具与变种

## 1. 内容的三种「卡」

| 类别 | 存在哪 | 玩家怎么用 | 规模 |
|---|---|---|---|
| **道具** item | `throw-loadout.ts` `ITEMS` | 放进 10 格巡演箱，出牌时按条件触发；相邻可增幅 | 1–3 格 |
| **遗物** relic | `throw-loadout.ts` `RELICS` | 每人一件，改一条全局规则 | — |
| **变种** enchant | `throw-enchant.ts` | 装在某张扑克牌的牌位上，这张牌被甩出时生效 | 稀有 8 / 史诗 4 / 传奇 3 张上限 |

另有**预设卡组**（`PRESETS`）：道具 + 遗物 + 克制声明 `beats` 的组合，供 AI 和练习场使用。

## 2. 设计语言：花色锁定状态

这是整个卡池的第一原则，所有新内容都要遵守：

| 花色 | 状态 | 家族 `family` | 图标底色 |
|---|---|---|---|
| ♠ 黑桃 | 护盾 | `shield` | `#4f7fae` |
| ♥ 红心 | 治疗 | `heal` | `#c98f7c` |
| ♣ 梅花 | 剧毒 | `poison` | `#6d9647` |
| ♦ 方块 | 灼烧 | `burn` | `#d0772f` |
| — | 直伤 | `damage` | `#b3263a` |
| — | 辅助（抽牌、增幅、净化） | `utility` | `#4fa39a` |

**为什么**：对手亮出的花色直接暴露他的意图，玩家「这手出几张哪种花色」就是战术决定。一件「每张 ♣ 加护盾」的道具会破坏这种可读性——不要做。

## 3. 克制环

v4 起，克制靠**机制**而不是数值。新内容要清楚自己站在环上的哪个位置。

| 克制 | 机制名 | 规则 |
|---|---|---|
| 治疗 → 剧毒 | 净化 | 每次治疗净化「名义治疗量一半」的剧毒，满血也生效 |
| 剧毒 → 护盾 | 绕盾 + 毒发 | 剧毒无视护盾；受害者每攒 5 张手牌，毒伤 +1 |
| 护盾 → 灼烧 | 闷火 | 有盾时新灼烧减半，灼烧只烧盾不伤血，并多退 2 层 |
| 灼烧 → 治疗 | 焦灼 + 烫手 | 着火时治疗只剩六成；灼烧 ≥3 层时每次出手自损 2 |
| 快甩 → 护盾 | 单张削盾 | 单张被盾挡下多耗 10%；铜镜不反射单张 |
| 快甩 → 剧毒 | 抖擞 | 抖擞披风每次出手净化 3 层毒 |
| 蓄爆 → 续航 | 压轴重创 | 顺子及以上命中，目标 5 秒内治疗六成 |
| 蓄爆 → 快甩 | 扇面格挡 | 手牌 ≥7 张时单张直伤减半 |
| 护盾 → 蓄爆 | 反击门槛 | 回声针盒只在被 ≥3 张命中时反击 |
| 存活 → 所有人 | 落幕 | 60 秒起双方每秒受递增伤害（v5） |

六套预设和它们声明的克制（`beats`）：

| 预设 | 克制 |
|---|---|
| 快甩 quick | 护灯、青苔 |
| 护灯 guard | 余烬、星光 |
| 余烬 burn | 回甘、快甩 |
| 回甘 mend | 青苔 |
| 青苔 poison | 护灯、星光 |
| 星光 combo | 回甘、快甩 |

详细推导见 `docs/F9_THROW_DECK_BALANCE_V4_2026-10-09.md`。

## 4. 设计一件新道具

### 4.1 数据格式

```ts
{
  id: 'stride',              // 稳定 id，小写英文，发布后不改
  name: '抖擞披风',           // 物件名：一件旧剧团里能找到的东西
  tag: '解毒',                // 2 字功能标签，显示在格子上
  size: 1,                   // 1–3 格
  family: 'utility',         // 决定图标底色和「护盾类」等分类
  text: '每次出手：净化自身 3 层剧毒。',      // 规则原文，逐字对应代码
  quip: '一直动来动去，毒都追不上。母亲说这叫“坐不住”。', // 俏皮话，见文案指南
}
```

### 4.2 文字规范

- 句式：**「触发条件：效果 数值。」**。例：`对子、两对或葫芦：护盾 +30。`、`每张♠：护盾 +14。`
- 术语只用这些：直伤、护盾、治疗、灼烧、剧毒、净化、迟缓、穿透、抽、力量、反击。新术语要先在规则弹窗里定义。
- 数值写死在文字里，不写「少量」「大幅」。
- 物件名是「旧剧团的旧东西」：伞、毯子、茶壶、闹钟、放映机、风扇。不要写「XX 之剑」「XX 护符」。
- 俏皮话遵守 `docs/F9_THROW_VOICE_GUIDE_2026-10-09.md`：英式冷幽默、轻描淡写、自嘲，不玩梗、不用网络流行语。

### 4.3 数值参考点

没有公式，但有一组已经过矩阵验证的锚点。新道具先和同尺寸、同家族的锚点比：

| 尺寸 | 锚点 | 说明 |
|---|---|---|
| 1 格 | 飞牌修缮箱：单张 +4 直伤 | 高频小收益 |
| 1 格 | 抖擞披风：每次出手净化 3 毒 | 纯反制，没有输出 |
| 1 格 | 浸露线盒 / 鼓火风扇：相邻 +50% | 增幅件，本身不产出 |
| 2 格 | 双响茶壶：对子类 +10 直伤 | 通用填充 |
| 2 格 | 补丁旧伞：对子类 +30 护盾 | 护盾数值 ≈ 直伤 ×3 |
| 2 格 | 守灯小毯 / 回暖小灯 / 青苔药匣 / 余烬小炉：每张对应花色 +14 盾 / 9 疗 / 3 毒 / 3 火 | 四个花色的「主引擎」，互为参照 |
| 3 格 | 织序风扇：顺子 +36，附带扇面格挡 | 苛刻条件 + 防守附加 |
| 3 格 | 护心放映机：附加当前护盾 50% 直伤 | 盾流的输出出口 |

经验法则：

- 条件越难满足，数值越大；但单件道具不能单独扭转一个克制关系。
- 持续状态（毒、火）每层价值远高于一次性直伤——毒每层都会每秒跳，所以基数要低。
- 无上限的成长（力量、叠层）必须封顶（`MAX_POWER = 30`）。
- **不要做「位置谜题」**（v4 删掉了「最左/最右格额外效果」）；相邻增幅是唯一的位置规则。

### 4.4 落地步骤

1. `ITEMS` 里加条目（4.1）。
2. `throw-duel.ts` 的 `itemEffects` 加一个 `case`，返回 `{ name, kind, value }` 列表。它同时服务预览和实际出牌。
3. 需要新的效果种类（`kind`）？在结算处加处理，并写机制测试。
4. `src/app/stage/glyphs.tsx` 的 `icons` 里画图标（见 04 第 5 节）。**没有图标测试会失败。**
5. 决定获取途径：起始箱、剧情奖励（`Reward.items`）、商店（`SHOP`）。
6. 如果是某个预设的一部分，更新 `PRESETS`，跑矩阵。
7. 单项测试 + 矩阵 + 剧情模拟（见 08）。

## 5. 设计一件新遗物

遗物改的是**规则**而不是数值：手牌上限、抽牌节奏、状态加成、反射。每套预设一件核心遗物。新遗物需要回答：「它让哪种打法第一次成立？」如果答案是「让某个已有打法更强」，那它应该是道具。

步骤同道具，效果代码不在 `itemEffects`，而是在对应的结算点（例：`handLimit(relic)`、反射在护盾吸收处）。

## 6. 设计牌的变种

### 6.1 结构

```ts
// 通用附魔（稀有/史诗），任何牌都能装
{ id: 'edge', rarity: 'rare', name: '磨边', text: '甩出时：直伤 +3。', quip: '…', effect: () => one('磨边', 'damage', 3) }

// 传奇附魔：每张牌一种，按 [花色][点数] 写在 LEGENDS 里，id 自动生成为 L + 花色字母 + 点数（例 LSJ = 黑桃 J）
11: { name: '伞兵杰克', text: '单张甩出：直伤 +8，穿透 30%。', quip: '…', effect: (c) => (single(c) ? [...] : []) },
```

可用字段：

| 字段 | 作用 |
|---|---|
| `points` | 点数倍率（镀金 ×2） |
| `plus` | 点数加值（描银 +4） |
| `wild` | 凑同花时当任意花色 |
| `weight` | 道具按「每张某花色」结算时算几张 |
| `effect(context)` | 甩出时的效果，可读取 `EnchantContext`：生命、护盾、自身/对手状态、手牌数、出手次数、是否落幕、是否在牌型里 |

### 6.2 稀有度规则

| 稀有度 | 定位 | 上限 |
|---|---|---|
| 普通（白牌） | 无附魔 | — |
| 稀有 | 一张牌一份小加成，≈ 1 格道具触发一次 | 8 |
| 史诗 | 改规则，或明显的数值（×2、百搭、共鸣、抽牌、穿透） | 4 |
| 传奇 | 每张牌专属，围绕该花色的状态，覆盖不同时机 | 3 |

传奇的分工（每个花色都照这个骨架写 13 张）：

- **2**：共鸣 ×3，放大本花色道具。
- **3–10**：分别覆盖单张、对子、顺子、同花、落幕、低血、对手状态、第 N 次出手等时机。
- **J**：单张的小技巧。
- **Q**：「夫人 / 女王」，通常读对手状态（对手的火、盾）或在落幕时爆发。
- **K**：百搭 + 本花色效果。
- **A**：本花色最强的单牌，通常在落幕时更强。

### 6.3 变种的硬规则

- 变种**不受相邻增幅**，防止和联灯接线盒叠成乘法爆炸。
- 变种**不改抽牌顺序**：牌匣只装饰牌，洗牌只看种子。
- 竞技预设和平衡回归测试一律用白牌；变种的强度在剧情里由敌人的牌匣抵消（见 06）。
- 文字和效果在同一行，改一个必须改另一个。

### 6.4 落地步骤

1. 在 `GENERIC` 或 `LEGENDS` 里加条目。
2. 新的 `kind`（如 `antidote`、`douse`）需要在 `throw-duel.ts` 结算处支持。
3. `throw-enchant.test.mjs` 加测试：触发 / 不触发 / 上限校验。
4. 跑「满牌匣 vs 白牌」对比（08 第 4 节），确认整体优势仍在 +25 个百分点左右，没有单一附魔独大。
5. 决定获取途径：商店（`SHOP` 里 `kind: 'variant'`，`ref` 写作 `'{suit}-{rank}:{id}'`，例 `'0-11:LSJ'`）或剧情奖励。

## 7. 已知的开放问题

**混搭构筑过强**：护盾 + 治疗 + 快甩的混搭对所有预设胜率 74–100%。消融实验显示每一块都有贡献；「催信闹钟」和护盾转伤的「护心放映机」会扭曲预设之间的对比。完整的构筑空间审计尚未做——**新增道具时请顺手用 `balance-matrix.mjs --kits` 测一下最强混搭**，不要让这个问题变得更严重。
