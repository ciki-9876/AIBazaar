# PRD v0.3 原型交付说明

2026-09-08：整合原始 v0.2 验收 JSON、有限维持配额、睡觉推进日期及三路天气方案。原始意见见 `reviews/f9-elevator-design-review-v02.json`，设计推导见 `COMBAT_WEATHER_DESIGN_2026-09-08.md`。

## 交付内容

- 九个独立模块仍位于 `/design/` 与 `/design/{module}/`，继续用原生文档链接，避免静态托管环境的客户端 RSC 跳转问题。
- 总览保留初始电梯叙事，并加入一天一次出勤的日程实验。世界、探索、基地页复用相同状态机，分别强调权限与目标、救援与安全容器、终端与睡觉；各页面样例状态相互独立。
- 配额每日扣减，救援额外扣减；普通包丢失，安全容器保留，原通关成绩保留。睡觉刷新出勤和每日生产额度。精力恢复、每日成本、救援成本及终端解锁曲线均明确标为建议。
- 背包扩容与现场鉴定支持五档概率、体积不变、重复请求幂等、扫描不推进日期。
- 卡牌页提供八张样卡，品质解锁条件效果、强化数值、不可培养的稀有度样本比较及拆解回收。
- 战斗页 A：三路九格，初始四格，天气与可轮换地形、摆牌与移动、三档品质、自动战斗和单步回放。
- 战斗页 B：独立的共享供能模式，关闭天气修饰，卡牌按优先级等待并消耗能量，手摇电芯可回复能量。
- 机器人页按日模拟 99 人配额、救援和永久淘汰；所有受影响楼层保留资源存量。
- 排名改为按通关高度与达标日数，旧成绩不因永久淘汰消失。

## 验收与版本

`lib/design-specs-v03.ts` 为新版 PRD 数据源，逐模块列出已确认前提、新建议、数据契约、边界及验收项。旧规格保留在 `design-specs.ts` 作为历史源。

新版使用 `f9.elevator.design.review.v03`，导出 `f9-elevator-design-review-v03.json`。不读取或覆盖 v0.2 的本机验收状态。新状态初始待验收；修改已确认项会恢复待验收。

- 32 项纯模型测试通过，覆盖旧引擎、新版日期与资源约束、救援、扫描、天气、确定性战斗以及机器人存量。
- TypeScript、lint 与静态导出用于验证页面代码；九模块和原游戏 HTTP 检查。
- 未进行浏览器截图或点击自动化测试，不能据此宣称实际浏览器所有交互已逐个验收。
- 这是一组可重置设计切片，不是完整的新游戏。未调用真实大模型，未实现服务器权威存档、跨页一局状态、近场机器人完整战斗、百层最终决斗、永久伤势、完整家具建造、便携回程器与真实任务解谜。
