# F9：房间内大模型行动、实时性与运行费用

日期：2026-10-03。状态：用户认可上一轮整体方向，具体落地继续讨论；下文架构、频率、模型分工与预算为提案，未接入服务、未实测。

后续 [Jev 可行性调研](./F9_JEV_FEASIBILITY_2026-10-03.md)提出更高频的主要战术模型候选：遭遇初测1–2Hz，保留生成式策略与本地连续执行。尚未选型或接入，不把下文5–15秒更新提案视为已定规则。

承接 [竞争者与淘汰方案](./F9_LLM_CONTESTANTS_AND_ELIMINATION_PROPOSAL_2026-10-03.md) 和 [ADR-0025](./design-log/decisions/ADR-0025-llm-contestants-and-elimination-experience.md)。用户询问真实行动、房间遭遇与战斗控制、模型实时性和费用。本轮不修改现行玩法或运行计费调用。

## 1. 结论与明确边界

可行方案是模型决定策略与短期战术，本地执行连续运动与自动战斗。云端模型逐帧返回方向不能作为可靠的即时战斗方案：网络、生成与推理都有延迟，吞吐速度也不等于有效行动的往返延迟。

因此即时躲避、碰撞和距离修正仍由算法完成。模型应拥有距离、方向偏好、站位目标、攻击对象、搜索中断条件、追击与撤离计划等具体控制权，而非只选择几个固定性格脚本。若要求每一次左右闪避都必须由生成式模型即时决定，此方案不能满足，需要另行研究本地学习型控制器及硬件，本文不承诺其可用性。

## 2. 真实行动与分工

| 行动 | 模型选择什么 | 世界执行什么 |
| --- | --- | --- |
| 探索 | 目标区域、沿哪条已知路线、是否绕开某人、何时撤离 | 按速度行走、碰撞、遮挡、揭示自己的视野 |
| 翻找与拾取 | 搜哪只柜子、搜到什么程度、遇到危险是否中断、取舍哪些物品 | 真实搜索时长、库存、占格、容器剩余物与可见声音 |
| 补给与装备 | 是否喝水、换哪件装备、如何布局、借出什么 | 和玩家相同的消耗、尺寸、相邻与使用效果 |
| 战斗拉扯 | 敌对对象、保持距离、绕行侧、遮挡锚点、进退与追击条件 | 连续选择可走方向、利用实际攻击范围、自动攻击与即时避险 |
| 合作与背叛 | 跟随、守点、共同搜索、拒绝支援、改约或转向别人 | 实际位置、交易、援助与承诺事件 |
| 资格博弈 | 报价、交换、转让、提交或拒绝；规则允许时投票 | 双方确认、原子支付、有限资源与公开晋级判定 |

中立人类不能因自动攻击默认成为敌对。主动敌对与结盟变化属于模型的有意义决定；遭受主动攻击后的即时自卫可由双方共同遵守的规则执行。AI 不可透视玩家背包、读取隐藏意图或使用玩家尚未表现过的攻击参数作精准预判。

现有模拟使用 `lib/survival-room.ts` 的 1/30 秒固定步长。这为新增角色的本地执行提供基线，不代表现在已有人类竞争者、完整导航或战术控制器；这些需要开发。

## 3. 三种时间尺度

| 层级 | 建议初值 | 内容 |
| --- | --- | --- |
| 本地动作 | 每模拟步，30 次／秒 | 移动、避障、保持距离、即时危险响应、自动攻击 |
| 模型短期战术 | 遭遇时约 5–15 秒一次，重要变化可提前触发 | 站位、拉扯方向、搜索计划、追击与撤离条件 |
| 模型长期判断 | 规则改变、关系变化、关键资源与谈判发生时 | 利益、联盟、承诺、路线目标与资格分配 |

这些是测试起点，不是固定频率保证。持续受击不应每帧触发请求；同一角色原则上只有一个待完成决策，合并新增观察，避免请求暴增。不同角色可并行推理，但保持独立的感知与记忆，不能因此共享秘密。

低层控制器可按模型提供的偏好连续评估候选移动方向：可通行性、与目标的距离、视线、自己攻击是否有效、可见威胁与退路。它不决定换盟友、不自主出卖资格、不凭默认脚本补一个战略背叛。模型的新计划可以改变这些偏好与目标。

同一“保持距离”能力因此可以用来掩护队友、拖延玩家、争取搜索时间或等待交易。固定的是动作能力与物理规则，行为意图和组合由模型决定。

## 4. 一次遭遇如何发生

模型不必阅读游戏截图。系统提供角色实际能感知的精简状态、已知地形／资源点标识、相对位置、可见威胁、自身装备、最近关系事件。选手对别人的攻击范围只能依靠公开展示或观察推断；自己武器参数可准确提供。

示例：选手持有已知射程 8 米的装备，观察到玩家的短程攻击。模型下达一个短期计划：

> 保持约 7–8 米，向已知东侧廊柱绕行，尽量保持攻击视线；暂时不进近身范围。如果玩家跟上，就沿预定路线退；自己的精神力低于阈值时停止纠缠，返回西门。

游戏立即执行，玩家一靠近，角色当步调整方向，不需要等下一次 API 回复。廊柱堵住攻击视线时，本地控制器在目标约束内重新找站位。若观察到新武器、退路被封或资源被抢，触发模型重规划；返回后可能改为脱战、寻求合作或继续施压。

模型也可提前为可能的遭遇给出条件计划：“遇到玩家先保持距离；对方攻击则撤向已知矮墙；若是甲则留出掩护路线。”条件分支由本次模型决定并保存，不是角色永久写死的反应脚本。这让首次露面不会站着等待网络。

必须承认边界：毫秒级闪避由本地控制器产生，模型在更新之间也可能错过快速战局变化。不能宣称每个细微动作都是模型即时推理所得。

## 5. 搜刮必须可被玩家打断与验证

“去搜柜子”要产生实际行走与翻找。玩家可以看见对方走近、停留、搜索动画、携带结果和撤离；也能抢先搜索、制造威胁、提出分工或把怪物引来。AI 持有与玩家相同的身体数值和背包限制，不能无限装物品或一边离开一边继续搜。

搜索时先执行模型给定的中断条件；若必须立即避开危险，暂停搜索并上报，待模型决定继续、放弃或反击。执行失败不能导致部分库存转移或免费奖励。离屏翻找同样需支付时间与占格，并保持唯一物品身份。

## 6. 离屏可以抽象，但不能随意生成结果

用户提出离屏使用算法、规则与模型生成结果，方向合理，前提是可见与不可见阶段共用一份权威世界状态。

建议分三种模拟精度：

- **远处区域**：模型给出行动计划，规则按区域路线、行程、搜索、补给和风险推进；用确定的行动时间和必要的随机输入产生结果。无需每帧画面或精细脚步。
- **接近玩家可感知范围**：预先恢复详细模拟，包括可能被看见、听见或即将进入的区域，保证突然转镜头时状态已经连续。
- **实际遭遇区域**：完整位置、碰撞、视野、搜索和战斗模拟。

离屏可以省模拟精度，不能省因果。必须保留从何处到何处、花了多少时间、哪个柜子被搜、哪些 UID 转移、谁知道了消息。不能让模型直接编“我已经搜完三只柜子、取得两枚签”，更不能预先承诺一个尚未发生的搜索结果。

未来行动只在合法完成的模拟时刻结算。玩家中途进入、抢先到达或打断时，取消或修正未完成事件。两人抢同一容器由实际完成顺序与明示冲突规则解决；不能双方都拿到奖励。

角色从离屏进入可见区域时沿既有行程出现，不为戏剧效果瞬移到玩家身后。精度切换必须保留生命状态、库存、剩余搜索时间和正在执行的计划；不能重复计算伤害或重新抽战利品。

## 7. 实时性与异常处理

官方延迟优化文档强调生成长度、模型选择、请求次数和并行化等因素；不能据此推断某次 F9 调用有固定毫秒响应保证。[OpenAI 官方建议](https://developers.openai.com/api/docs/guides/latency-optimization)

第一版应测量：从观察快照建立，到完整有效计划经过校验并开始执行的总延迟。首 token 出现和流式文本开始显示不是可执行计划已经返回。语法约束也不能保证语义有效。

建议把战术调用 P95 不超过 2 秒作为试验验收目标，并测 P50、P95、P99、无效结果率与过期率；这是要求，不是当前模型的已知实测性能。动作在下一模拟步响应，也仅指本地控制器已有合法策略可执行，不包括模型往返。

等待期间执行旧计划和旧计划里的条件反应。新计划先重新校验目标、资源与观察时效；敌人已经离场、柜子已空、交易条件不成立时不能照旧执行。不得根据返回时刻快慢决定谈判先手或晋级顺序。

长时间不可用时暂停／存档重试；不要为了不断流而让本地脚本替选手选择重大结盟、投票与资格转移。模型不确定性与游戏帧率分开处理。

## 8. 模型分工候选

首轮可测试 GPT-6 Luna 做窄范围战术，GPT-6.1 Sol 做角色策略与谈判，GPT-6 Astra 作质量对照或少量复杂决策。这个推荐基于官方任务定位与价格，不是三者在 F9 中已通过评测。廉价模型若不能保持战术质量，就必须提高层级或降低调用规模，不能只以账单选择。

官方文档显示：Luna 支持无推理模式；Sol 的最低推理等级是 low，不支持 none／minimal；Astra 支持 low 等等级。不能假定所有模型都能完全关闭内部推理。[Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)、[Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)

不同模型共用选手档案与事件记忆，但短期战术模型不能擅自推翻已提交的交易或改变联盟；需要战略层重新决定并正式记录。分工不等于一个模型读取所有人的秘密。

## 9. 费用：官方单价与预算假设

核对日期 2026-10-03。采用 Standard、短上下文文本 API 价格，每百万 token 美元；未申请实际账户，价格不代表账户可用性。

| 模型 | 未缓存输入 | 缓存输入 | 缓存写入 | 计费输出 |
| --- | ---: | ---: | ---: | ---: |
| GPT-6 Luna | $0.10 | $0.01 | $0.125 | $0.50 |
| GPT-6.1 Sol | $2.00 | $0.10 | $2.50 | $10.00 |
| GPT-6 Astra | $10.00 | $1.00 | $12.50 | $50.00 |

来源：[OpenAI API 价格](https://developers.openai.com/api/docs/pricing)及上述各模型官方页。Fast 模式价格是 Standard 的两倍；下表不使用 Fast，也不采用不适合实时遭遇的 Batch／Flex 折扣。

为便于人民币预算，**假设 $1＝¥7.20，不是实时汇率**。每次短决策暂按输入 2,000 token、计费输出 500 token；输出已经包含内部推理，不能只统计屏幕可见文本。这是人为核算场景，尚无真实使用量证据。500 token 也不是给推理模型设置硬上限的建议。

| 全部短决策采用同一模型 | 每次决策 | 一次 60 秒遭遇，5 秒一次，共 12 次 | 三名 AI、10 分钟一期，平均每 10 秒一次，共 180 次 |
| --- | ---: | ---: | ---: |
| Luna | ¥0.00324 | ¥0.039 | ¥0.58 |
| Sol | ¥0.0648 | ¥0.78 | ¥11.66 |
| Astra | ¥0.324 | ¥3.89 | ¥58.32 |

两个频率例子分别计算，不暗示每场遭遇都刚好五秒一次，或每期每个角色必须调用六十次。表中不包含额外长谈判、总结、失败重试、语音、服务器、支付费用与税费，也未计缓存收益或写入费用。

计算式：人民币费用＝（输入 token×输入单价＋计费输出 token×输出单价）÷1,000,000×7.20。实际启用缓存时按写入、读取和未缓存输入分别核算。

### 9.1 混合分工示例

短战术 180 次用 Luna；另加 15 次重要策略／谈判用 Sol，每次按输入 4,000、计费输出 2,000 token：

- 短战术：¥0.5832。
- 长决策：每次 ¥0.2016，15 次合计 ¥3.024。
- 一期合计 **¥3.6072，约 ¥3.61**。
- 假定六期都具有完全相同负载，则一季约 **¥21.64**；真实淘汰会减少后续活跃人数，长谈判也可能增多，不能把此数当单季定价承诺。

### 9.2 需要特别控制的变量

推理 token 以输出计费，官方说明复杂问题可能用数百至数万推理 token。[推理与成本文档](https://developers.openai.com/api/docs/guides/reasoning)

例如 Astra 输入仍为 2,000，计费输出由 500 变成 5,000，则单次约 ¥1.944，是原场景六倍；180 次约 ¥349.92。设置过小输出上限可能在有效计划出现前用完预算，随后重试反而更贵。控制语义复杂度、短计划和推理等级后仍需记录真实 usage。

固定人物资料、工具定义和规则可以测试缓存；改变动态状态不保证自动命中同一前缀，缓存写入也有费用，不能预设每次都享受折扣。[缓存规则](https://developers.openai.com/api/docs/guides/prompt-caching)

每个玩家的每一季都会产生运行成本，无法只计算开发时的一次生成费。商业预算必须乘以活跃玩家与游玩次数，并为重试、异常和额外交涉留余量。本文不设计付费 UI 或商业模式。

## 10. 最小验证建议

先用一间现有主题房间和一名竞争者，验证移动、搜索、被玩家抢先、远程拉扯与脱战五种情景；固定角色关系和装备，用模型真实生成计划。并记录延迟、输入、推理／可见输出、无效／过期计划，以及资源身份和动作轨迹。

重点检查：模型是否能选择并改变战术，本地动作是否流畅，离屏与可见状态是否连续，玩家是否能凭走位反制，费用是否符合实际预算。验证后才扩展三名选手与晋级谈判。

测试不直接修改历史 RNG、黄金回放或旧存档。模型调用结果作为外部决策记录；固定模拟 tick 执行已验证计划，回放不重新调用模型。失败动作保持原子性，电梯模块不导入卡牌或实验业务。
