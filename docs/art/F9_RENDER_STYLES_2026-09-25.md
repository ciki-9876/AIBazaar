## 保留边界与实现

**未修改原模型、材质、贴图及物件 shader**；新增的是屏幕空间后处理 shader。这一区别是本轮约束的关键，不应描述为“完全不用 shader”。

原场景输出线性颜色与深度 → `OutputPass` 沿用既有曝光/色调映射并转换到 sRGB → 单次艺术后处理 → 屏幕。颜色与深度提供轮廓，不额外替换全场材质来输出法线。透明卡牌光环按 alpha 处理，避免变成不透明圆盘。

依据：[Three.js OutputPass](https://threejs.org/docs/pages/OutputPass.html) 与 [颜色管理](https://threejs.org/manual/pages/color-management.html)。原画与风格分屏采样同一帧，避免分别渲染导致动作时间不同。

- 新增 `app/art/styles/page.tsx`：演示与交互，直接复用卡牌/战场组件。
- 新增 `app/art/styles/post-process.ts`：离屏目标、深度轮廓、五种艺术处理、尺寸更新和资源释放。
- 新增 `app/art/styles/presets.ts`、`styles.css`：风格元信息与自适应布局。
- `app/art/cards/scene.tsx`、`app/art/slice/scene.tsx`：仅添加可选后处理渲染入口及销毁。没有传入配置的既有页面继续直接渲染。
- 无依赖新增，无存档读取/写入，无正式卡牌或战斗规则修改。

## 视觉判断及风险

1. **能力边界**：可在不重做资产的前提下获得五套明显不同的画面语言。但屏幕空间只知道可见颜色和深度；不能推断人脸区域、重新绘制二次元五官、重组水墨笔势或调整物件轮廓。水墨样例更接近水墨化滤绘，不能等同画师手绘。
2. **卡牌可读性**：现有卡面字印在模型贴图上，也会被处理。网点、版画、霓虹满强度会破坏小字；演示提供原画、强度与独立能力说明。正式接入时应将关键文字单独覆盖在后处理之后，或增加文字保护遮罩；本轮未改原卡面资产。
3. **战术色彩**：黑白风格会消除材质原本的阵营/品质颜色。演示保留 HTML 血量和时间；正式战斗需另行验收路线、目标和品质识别，不能只依赖颜色。
4. **性能**：额外半浮点颜色/深度目标、输出转换及多采样艺术处理带来 GPU 成本。已检查本机交互，尚未做低端集显、移动端、长时间显存或帧率基准，不宣称所有设备稳定 60 fps。
5. **推荐仍是判断**：赛璐璐更适合继续验证整场战斗；版画适合作为卡牌收藏/档案视觉实验；霓虹可作为异常侦测视角。尚未取得用户风格选择，不替换已接受的非像素材质方向。
