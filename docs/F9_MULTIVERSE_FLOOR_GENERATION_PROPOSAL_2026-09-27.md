# F9 多时空楼层生成提案

后续状态：用户已采纳资产包方向，要求同主题通过配色、陈设复用，并先做中国风。决定和首版边界见 [ADR-0021](./design-log/decisions/ADR-0021-themed-kits-and-jiangnan-sample.md)。以下保留原提案，不将其全部视为已实现。

2026-09-27。状态：待讨论；用户确定“主题可跨越沙漠、中国楼阁、魔法、卡通，整体视觉应显著不同”，以下架构与制作节奏为建议。当前已经有荒原、重构维保廊和第三层沙岩入口，不表示下述完整生成器已完成。

## 判断

建议采用“主题资产包 + 空间语法 + 简短楼层配方 + 确定性展开”。节省的是逐个物件编写代码和逐层重复描述的成本，不应省去首次主题美术设计。

全靠换颜色、雾和装饰密度，仍会被认作同一张地图。完全让模型逐层编写新场景又会耗费大量 token，产生质量波动、重复碰撞错误和版本维护负担。运行时生成楼层不需要调用语言模型。

## 四层分工

| 层 | 内容 | 制作频率 |
| --- | --- | --- |
| 玩法骨架 | 电梯、可达区域、主环路、支路、资源与风险分布、撤退距离 | 一套核心，若干拓扑模板 |
| 主题资产包 | 地形材质、建筑轮廓、专属地标、遮挡物、光影、雾、天空、声音、表现方式 | 每个新主题认真做一次 |
| 空间语法 | 该世界如何生长：山脊／沙谷、院落／廊道、漂浮台／桥、弧形街／玩具岛 | 每主题 2–4 种结构起步 |
| 楼层配方 | 主题、语法、种子、规模、风险节奏、地标、资源预算、变体参数 | 每层约十几个参数；由程序展开 |

示意配方（不是当前可直接执行的接口）：

```json
{
  "floor": 12,
  "theme": "ink-pavilion-v1",
  "grammar": "courtyard-three-loops",
  "seed": 120731,
  "area": 4200,
  "landmark": "hanging-bell-tower",
  "lighting": "rain-before-dawn",
  "routeRisk": 2,
  "supplyBudget": 18,
  "variants": ["flooded-west-court", "broken-gallery"]
}
```

配方只有描述世界选择的参数，不携带数百个物件。工具只返回验证结果、统计和少量缩略图，避免把展开的场景重新塞回上下文。

## 怎样保证“门外真是另一个世界”

每个主题先交付一张能代表它的入口镜头，再扩展生成。每张楼层至少有一个远景或中景可辨识地标，重点雕琢可见入口、任务点和回程地标；边缘杂物通过实例化规则批量铺设。

| 主题 | 主要轮廓与空间 | 材质／光影／氛围 | 独占的关键资产 |
| --- | --- | --- | --- |
| 风蚀沙漠 | 宽阔沙谷、风脊、半埋遗迹、细长阴影 | 哑光沙粒、暖沙冷影、远处尘幕 | 巨型残门、风蚀拱、斜埋雕像 |
| 中国楼阁 | 庭院、曲折连廊、层叠屋檐、门洞框景 | 木、瓦、湿石、水墨式明暗、雨雾 | 飞檐、斗拱、牌楼、悬钟 |
| 魔法世界 | 悬浮台、环状遗迹、桥、反重力构件 | 冷暖发光层次、晶体、低亮魔法尘 | 漂浮巨环、法阵柱、悬空书库 |
| 卡通世界 | 夸张比例、弧形街道、玩具构件、较少碎细节 | 大色块、硬阴影、可独立配置描边 | 弹性屋顶、巨型日用品、纸片树 |

复用的是碰撞、交互、容器、门、粒子、植被生成与散布工具；显著的屋檐、沙谷、法阵、卡通轮廓应来自不同主题模块。相同“矮墙”机制可以有石垣、残墙、晶簇、玩具积木等外观，但必须保证高度、碰撞和可见性语义一致。

画风跨越需要主题级材质与后处理预设，不能只换贴图。玩家、装备栏和危险信号可保持稳定，以免世界变化也破坏操作识别。魔法世界的悬空平台还需为行走掩码、落差和桥增加能力，当前平面房间系统不能仅换美术就假装支持。

## 确定性与自动验收

- 同配方、版本和种子得到同一份物件清单、UID、碰撞与掉落；重进已访问楼层不洗牌，不复活一次性 BOSS。
- 保存生成版本与已展开清单的快照／兼容版本。新资产包不能悄悄重排旧存档。
- 先检查电梯到任务点、补给点、BOSS 与返回路线的可达性，再装饰；明确最低通路宽度、最长无补给距离、有效躲避空间、镜头遮挡阈值。
- 高层封闭低层后，必须保证当前或更高楼层仍能获得成长所需资源，禁止配方要求已永久错过的低层专属材料。
- 地表与远景延伸越过空气墙，边界通过主题适合的雾、风沙、云海或浓荫软化；不能摆一圈显眼岩石代替世界边缘。
- 每次只输出几张固定机位图、俯视碰撞图、连通性结果和预算统计；失败时修改配方／规则，而非手改几十个生成实例。

## 建议下一步

先以“灰暗维保廊 → 风蚀沙漠 → 雨夜楼阁”三个轮廓差别最大的主题做验证：每个主题两种空间语法、每种十个种子。判断标准是入口一眼能区分世界，路线能稳定成立，返程与搜刮不被主题遮挡破坏。

先把沙漠和楼阁各做一个高质量样板，再从样板提炼资产包。若先造一个无边界的万能生成器，容易获得很多地图，却没有一个足够好看的世界。

“无限楼层，每层完全新美术，成本几乎不增加”并不现实。可行目标是有限而精致的主题库，通过独有空间语法、地标组合、天气与时段产生大量有差别的楼层。新增主题的首次制作仍有真实成本；楼层越大、重复对象越多，规则展开节省的 token 越明显。
