# 《最后一张王牌》像素场景 V2 美术验收标准

日期：2026-10-04。作者：独立美术审查子任务。

状态：**验收门槛与初查历史保留；正常WebGL路径的最终实机结果见本文件“最终浏览器验收”及[本轮记录](./design-log/iterations/F9/2026-10-04-throw-pixel-atomic-lighting.md)。** 初查部分的“未验证”是形成该检查时的状态，不自动代替最终结论。数字是本轮美术标尺，不改变甩牌战斗规则。

## 用户明确要求

- 场景拆成可独立打磨、重复使用的原子资产。
- 灯光在运行时渲染，角色与 NPC 具有流畅的帧动画。
- 修正室内角色像小人、家具像巨物的比例。
- 降低上一版像素精度，并以严格标准进行浏览器验收。

## 已观察到的旧版问题

用户截图的工作室中，门洞约为人物身高的三倍，桌面高于人物头顶，无法解释为正常成人使用的家具。误差来自背景与角色各自缩放，没有共同尺寸标尺。

旧 `CharacterSprite` 用四列 `1774×887` 图集和三列 `1752×898` 图集直接做 CSS 百分比采样。前者每格宽 443.5，采样边界和脚底不能准确注册到共同整数网格；后者 NPC 每人只有一帧。玩家与 NPC 外层又分别使用 `translateY(-88%)` 与 `translateY(-95%)`，透明留白改变脚底位置。

旧场景是整幅图片，灯具、墙、桌、地板不能独立布置；两个固定 CSS 光晕没有使用实际灯具坐标，也未改变移动角色受光。图片里的暖光属于原画，不能据此声称实现动态光照。

## 1. 比例：全部实体使用一把尺

统一标尺：**1 原生像素 = 4 世界单位**。推荐成人角色可见身高 48 原生像素，即 192 世界单位。角色尺寸按可见轮廓计算，不能把透明边距算进身高。

| 对象 | 推荐原生尺寸 | 与成人身高的关系 | 判定方法 |
| --- | --- | --- | --- |
| 主角 / 成人 NPC | 身高 44–50 像素 | 0.92–1.04 | 同一地面并排观察 |
| 门洞净高 | 60–70 像素 | 1.25–1.46 | 头顶有余量，但不能像仓库巨门 |
| 普通桌面离地 | 22–28 像素 | 0.46–0.58 | 桌面在角色腰部附近 |
| 座椅坐面离地 | 12–16 像素 | 0.25–0.33 | 与桌面组成可信家具 |
| 独立落地柜 | 46–60 像素 | 0.96–1.25 | 常用层能被人物手臂触及 |
| 普通门宽 | 26–38 像素 | 0.54–0.79 | 人物能通过，双扇门另标注 |

门洞 64 像素 / 角色 48 像素 / 桌高 24 像素是本轮可用基准。窗、书架、帷幕可以更高，但必须明确位于后墙，不能拿巨大墙面陈设掩盖桌椅失真。

必须在主角站在门边、桌边、导师身边时分别截图。至少一张不显示对话框，让完整脚底与家具底边可见。角色、桌腿、门槛的地面关系由同一世界坐标确定；不得依靠每张图不同的百分比偏移补救。

## 2. 像素语言：降精度不等于把旧画模糊

- 场景、人物、可移动道具在同一原生画布中以最近邻方式绘制。放大后能辨识统一的像素阶梯。
- 原生采样坐标、帧矩形、角色脚底锚点均为整数。不能从跨帧边界的半像素位置读取图集。
- 角色头部约 9–13 像素、眼睛约 1–2 像素；面部用轮廓和色块表达，避免缩成噪声的写实五官。
- 桌、门、灯等物件的内部材质用 2–5 个主要明度块和有方向的少量纹理表达。不能用密集随机亮点模拟“精致”。
- 外轮廓、主角红围巾、导师浅发、道具轮廓在实际游戏倍率下清晰；不能只有放大资产图时能辨认。
- 动态灯光允许生成连续照明值，但结果必须在同一原生网格上采样；UI 文本可在屏幕分辨率绘制，不能反过来改变世界像素大小。
- 响应式缩放优先选择整数屏幕倍率或明确的最近邻填充方式；避免背景、角色分别采用不同小数倍率造成细边闪烁。

验收时查看普通截图与局部近看，并横向走过有高对比边缘的门框。若人物在运动时轮廓交替变粗变细、静物纹理爬动、不同资产像素块大小明显不一致，判失败。

## 3. 分层与原子资产

场景实例应描述摆放方式，资产负责形象；能在不重新生成整张场景的条件下移动、替换、复用一张桌、一盏灯、一扇门。

| 层 | 典型内容 | 要求 |
| --- | --- | --- |
| 远景 | 天空、远处街区、窗外景 | 不画入主角、室内家具或热点标签 |
| 建筑 | 墙块、门框、窗框、地板 | 门口与实际交互点重合 |
| 后层道具 | 书架、墙画、帷幕 | 独立透明资产，尺度受标尺约束 |
| 人物 / 互动层 | 主角、NPC、独立交互物 | 脚底锚定，灯光共同作用 |
| 前景 | 近处栏杆、地毯边、少量遮挡物 | 不遮挡交互对象的身体主体和出口 |
| 光源与遮挡 | 台灯、壁灯、窗光、实体挡光轮廓 | 灯具图像与光源配置分离且绑定坐标 |

最低可复用证明：同一盏壁灯或同一家具资产在两个场景实例中使用；主角进入屋内后保留同一角色图集，不能替换为室内专用缩小人物。每个图集都应有可追踪的帧矩形、锚点、尺寸与来源。

角色、NPC、光照不得烘焙进背景。环境原画中可保留材料自身的阴影，但一盏灯打开/关闭造成的亮暗必须由运行时产生。

## 4. 光照：动态受光是必须项

合格的二维实时光照最低包含：环境光、带颜色和衰减的局部光源、灯具位置、对场景和移动人物的共同作用。若实现实体遮挡，则应额外验证阴影是否随光源与遮挡关系更新；不以 CSS 全屏暗色遮罩和固定发光圈充当这些行为。

- 暖灯附近的衣服、地板、墙和家具同时受暖光；角色离开时逐渐恢复环境色，不能只背景发亮、人物保持全程同一颜色。
- 暖灯与冷窗的受光方向可辨，暗处人物仍能辨认轮廓；不允许角色全黑消失，也不允许全场均匀发亮失去光源。
- 若关掉场景局部光源，灯附近的照明必须相应减弱。若暂不提供面向玩家的开关，应由开发验收中相同场景的开/关截图证明。
- 移动镜头时光斑与灯具共同移动。光斑不能固定在屏幕角落；人物或场景不能使用不同 camera/scale 导致受光位置漂移。
- 壁灯和台灯避免不合物理关系的巨大光盘；亮点先落在灯芯，较亮面集中在灯下或灯旁，远处按距离下降。
- 光照结果不得洗掉人物肤色、红围巾与紫/青衣服区别，不得引入截图上随机爆白点。

浏览器对比路线：暗区站立 → 走近暖灯 → 灯下站立 → 转身走向冷窗。保存至少两个位置的完整场景截图，检查人物和环境一起变化。运行时持续更新证据与静态截图应分开记录。

## 5. 帧动画：不能靠整个纸片上下浮动

推荐主角 8 帧行走，约 10–12 帧/秒；每个 NPC 至少有自己的 4 帧待机/呼吸/眨眼变化。帧数是目标，不是质量证明；如果四帧明显足够流畅，需用实际运行证据解释，而非自行标记八帧等价。

- 所有帧使用同一透明格、脚底锚点、头部尺寸和衣服轮廓。全幅外接框变化不能造成角色左右跳跃。
- 步行出现明确左右脚交替、摆臂与围巾或衣摆二级运动；不能只是镜像一张站姿或整体平移抖动。
- 接触脚的落地基线变化最多 1 原生像素。头部允许 1 原生像素节奏起伏；身体不能每帧整体漂浮 3–4 像素。
- 动画帧与空间位移协同：止步立即回到完整站姿，人物到地图边界停住后不能持续原地快走；对话时不继续走动。
- NPC 静止时微动画仍应更新，不应依赖玩家的 `walkTicks`；呼吸和眨眼可以异步，避免三位 NPC 同时像钟摆一样摆动。
- 转向使用同一脚底 pivot，切换朝向后位置不跳；左行与右行速度一致。
- 动画时间属于表现层，不能写入战斗 RNG 或改变确定性冒险结果。

浏览器观察需持续至少两个步行循环，而不是只展示一张行走截图。分别检查左行、右行、快速转向、到门前停止、对话后恢复、NPC 独立待机。若关键姿势中腿重叠、围巾断裂、头发变形、透明背景漏入相邻帧，即判失败并修正图集。

## 6. 可读视口与交互往返

至少检查 1920×1080、1280×720、1024×600，另检查 390×844 作为窄窗回归。尺寸是验收覆盖建议，不是实际完成声明。

- 桌面一屏显示完整角色脚底、当前附近的交互提示、对话继续按钮和底部行走按钮；页面本身无纵向滚动。
- 室内不能靠空白左右边栏把人缩小来凑整幅背景。镜头应服务人物和可到达的热点。
- 对话框可以遮挡一部分场景，但姓名、正文、动作按钮完整可见。聚焦按钮不把整个游戏视口滚走。
- 左右镜头边界停稳；建筑入口处没有在一帧内弹出全新比例或场景瞬移错位。
- 键盘与点击地点都真实移动到对象附近才交互；保持本轮无跳跃、现有练习与资格战斗结果逻辑。
- 房间进入 → NPC 对话 → 练习战斗 → 返回原房间与原位置 → 出门，必须实际操作通过。不能仅因页面成功加载或规则测试通过就标记完成。

## 7. 自动化检查的边界

推荐新增的是资产/场景数据的完整性和可用性测试，而非复制绘图函数来证明自己：

1. 资产清单所引用文件存在；帧矩形在图集内部；帧格与 pivot 为整数；站姿和行走帧不会读到其他角色格。
2. 所有可进入建筑有可用的门洞实例，门高与人物身高的比例落在允许范围；所有NPC脚底与当前地图地面相符。
3. 整理同一场景实例的光源和遮挡输入，确认光照采样在靠近光源时提高、远离时降低；存在挡光体时，不相关位置不能被全局熄灭。
4. 改变相机位置只改变渲染坐标，不改变世界实体坐标、行走结果、交互范围或战斗种子。
5. 极小/极大视口、长时间动画输入不产生 NaN、越界采样或资源泄漏；切图后不保留上一房间光源。

像素美感、帧间体型一致、脚底不滑动、灯光是否自然，必须由实机人工审查。自动化通过只能证明对应数据和行为性质，不能取代这些观察。

## 验收记录格式

最终记录每项为“通过 / 修复后通过 / 未通过 / 未验证”，附实际场景、视口、操作与截图。应写出被否决的比例或帧动画缺陷，以及如何修正；没有观察到的灯光遮挡或 NPC 行走不要自动升级为已实现。PNG 文件数、生成分辨率和测试数量本身都不是像素美术验收结论。
