## 1. 具体路线

采用「个人观察 → 合法行动候选 → 模型选择 → 确定性执行 → 结果记录」。
每次动作包含目标和参数，模型只返回候选 ID。程序负责碰撞、路径执行、自动攻击、翻找时间、补给和资源结算；模型负责选哪项。

不从零预训练通用语言模型。先让游戏产生可复核的决策任务，再以 Laya 多语基础作为领域训练对照，和专用结构化模型比较。
是否采用、扩大模型或蒸馏，依据闭环行为及两端性能，不能仅依据一次推理速度。

| 阶段 | 实际交付 | 验收方式 | 本轮状态 |
| --- | --- | --- | --- |
| 0：实验底座 | 观察隔离、候选、动作提交、训练记录、学习模型、离线评测、浏览器线程接口 | 看不到隐藏信息；失败不扣物品；记录可回放；两端选择一致 | 已完成下述最小范围 |
| 1：一名真实竞争者 | 玩家与AI在同一测试房间中共存；各自视野、物品所有权、搜索和自动攻击 | AI确实移动、拿走资源和撤退；能被遮挡与走位反制 | 尚未实装，下一步 |
| 2：领域训练 | 真实遭遇数据、冲突情境、Laya原始/领域训练对照、短战术模型 | 分组留出 + 多步闭环，记录错误原因，而非只报分类准确率 | 尚未下载或训练Laya |
| 3：博弈切片 | 2–3名选手、承诺、交易、资格争夺、个人事件记忆 | 话语影响后续行动；资源代价和背约后果真实存在；不同人物会改变选择 | 待具体规则与实现 |

但当前游戏还没有独立人类竞争者与交易规则，不能将测试角色身体冒充已经可玩的竞争者。

## 2. 第一阶段已经做了什么

- `lib/survival-ai/`：版本化观察/候选/回复协议、运行时校验、执行器、数据与监督学习流程。
- 只读取自身信息、当前可见怪物和资源点。密封箱柜不暴露内容、品质或价值；隐藏怪物、世界种子和RNG不进入模型输入。
- 目前支持等待、八方向局部移动、靠近/翻找容器、主动补给、开始/继续撤离。候选绑定稳定请求 ID，回复有效期30个模拟tick，即当前规则下1秒，属于实验参数。
- 移动只支持当前可见、直达的局部目标；最多纳入三个可见资源点。没有已探索地图寻路、远程目标、谈判、装备重排或跨期记忆。
- 执行器复查当前目标/物品/遮挡；拒绝过期、串角色、未知候选和携带额外动作参数的回复。无效动作保留原状态。
- 测试身体复用现有 `SurvivalState.player` 槽位，运行原搜索、饥渴、自动战斗和撤离规则；没有修改生产模拟或增加多角色规则。
- 记录请求、实际选择、执行收据与短期结果；回放使用记录的选择，不重新调用模型。
- 同一轻量权重能在Node与浏览器Worker中选择行动。浏览器入口不会在主线程跑网络计算。

### 实验模型的准确定位

本轮训练了一个 **721参数、28维结构化输入、24个隐藏单元的MLP候选排序器**，参数确实由监督训练更新。
目的只是检查训练、导出、推理和执行是否连通；不是Jev复刻、Laya微调版或正式游戏AI。

60条助手编写的合成快照来自15个情境，每种4个数值变体：
训练32、校准12、测试16。按seed、轨迹、情境模板和关系分组禁止跨区泄漏。
支持多个可接受行动；标签来源明确为 `synthetic-smoke`，没有伪装成人类验收。

这些情境很简单，也不构成独立玩家策略、未知主题或长期关系的泛化评测。
校准分区目前只预留和报告，没有置信度校准或风险门控。所有静态快照符合示范，不能据此宣称“100%智能”。

## 3. 当前实测与验证

以下是这台Windows电脑上的单次实验，不是最终性能承诺：

| 检查 | 结果 | 适用边界 |
| --- | --- | --- |
| 本地训练 | 约0.37秒；权重JSON 15,290字节 | 721参数模型与60条合成样本，不是Laya训练时间 |
| Node热启动推理 | 1000次，P95约0.032毫秒 | 空载CPU；不包含游戏渲染、候选生成或完整动作执行 |
| 浏览器Worker | 覆盖60局面；200次计时；与Node选择一致，无重复决定漂移 | 当前内嵌浏览器；同一小网络，非所有设备/浏览器保证 |
| Worker载入/往返 | 载入约6毫秒，热启动往返P95约0.3毫秒 | 模型传递、校验与消息往返；不代表大型模型下载/冷启动 |
| 浏览器内推理 | P95约0.1毫秒 | 浏览器计时精度有限，不代表Laya/生成模型速度 |
| 固定遭遇闭环 | 15段，实际翻找、补给、战斗与撤离；全部记录回放状态一致 | 每段最多300tick，关闭新波次；不是玩家对AI的胜率 |
| 行为与协议测试 | 11项专项检查通过 | 信息隔离、遮挡、非法/过期回复、原子使用、分组隔离、训练与回放 |

全库316项测试通过；lint、typecheck、产品边界、确定性与依赖检查通过。独立Worker构建通过；本轮未改生产路由或构建配置，因此没有重建两个完整产品。

现阶段没有GPU训练、ONNX导出、生成式对话或生产客户端打包。
小游戏规则的确定性与模型浮点计算的跨设备一致性是两件事；正式回放仍以提交的动作记录为依据。

## 4. 接下来如何训练Laya

1. 先接一名竞争者，保证观察和候选确实覆盖现场可做的取舍。补已探索地图导航，保留角色各自的有限知识。
2. 我整理几十个冲突情境，你评判其中最有代表性的5–10个；变成行为示范、偏好对和失败样本。理由供复核，不当作执行结果。
3. 收集真实执行轨迹；首个领域试验可从约1000–2000个有覆盖的决策情境起步，数量是规划值，不保证足够。不要靠同一局的相邻帧凑数。
4. 在独立Python环境固定Laya代码/检查点版本。先测原始模型，再从冻结编码器、训练决策头等较小配置起步；实测显存后再决定是否扩大训练。
5. 使用留出的校准数据做置信度校准；最终测试保持独立。原始Laya、训练后Laya、小策略网络和规则对照使用同一局面与评测口径。
6. 记录绕圈、搜刮中断、错补给、冒险失败、目标达成与承诺兑现。只有短战术有效，再决定量化/蒸馏；教师选错时先修任务与数据。

训练预算由实测吞吐、显存、样本覆盖和错误来源决定。本轮不承诺若干小时就能得到会博弈的AI，也没有使用收费API。

## 5. 开放博弈怎么保留

快决策模型适合已有策略下的短期取舍。它不会因为训练了追逃就自动理解任意中文谈判。

若希望运行API费用为零且仍有开放交涉，后续候选架构是：
低频本地生成式模型决定策略/理解提议，快模型执行短战术，游戏结算真实行为；各选手共享权重但有独立记忆和知识。

这一层尚未选型。Windows可先测本地生成模型，浏览器必须独立测试下载、内存和实际对话延迟；不能默认客户端的模型一定能搬进浏览器。
如果最终只能做有限菜单或模板对白，需要明确这是体验范围的改变，不能悄悄替代用户要求。

## 6. 你需要准备什么

**现在不需要新增硬件、购买API额度，也不需要自己编码或制作数据文件。**

本机实测配置：
i5-12600KF、RTX4070约12GB显存、32GB内存；C盘约108GiB、D盘约247GiB可用。
这足够启动实验；不等于保证12GB能跑任意Laya全量微调或生成模型。先测实际显存，再调整训练范围。
之后暂留约20–40GB用于独立训练环境、权重和检查点，这是规划空间而非本轮实际占用。

你最值得准备的材料：

- **3种人物倾向**：他在乎什么、害怕失去什么、哪些事不能接受。例如“重视承诺但不愿白白送死”，而不是“永远救人”的固定脚本。
- **5–10个博弈局面**：想看到什么取舍、为什么。如只剩一瓶水/承诺等人但撤离将截止/竞争对手刚救过自己。可以直接用自然语言描述。
- **试玩判断**：哪些选择让你觉得它像有自己目的的人，哪些只是机械反应。相比批量买模型或堆样本，这更能定义模型应学什么。

这些材料不阻碍阶段1的代码工作；未提供时我先整理候选案例，你再挑刺。
最低发行硬件、目标浏览器和是否要求全部功能离线，可在第一轮真实遭遇后再确定。

## 7. 如何运行本轮实验

在本工作区根目录，Node22.13以上并安装仓库依赖后：

```powershell
node apps/elevator/ai-lab/run.mjs
node apps/elevator/ai-lab/serve.mjs
```

访问 `http://127.0.0.1:4191`，点击「验证浏览器推理」。
生成数据位于 `outputs/f9-local-ai/`，被仓库忽略；包括模型、评测、复核JSONL、执行轨迹与回放。
复核格式是我们自己的交换契约，尚未宣称可以不经适配直接交给上游Laya训练API。

专项检查：`node --test lib/survival-ai/decision-pipeline.test.mjs`。
正式游戏入口不变。下一步交付目标是一名真正与玩家共享房间、独立持有物品的模型竞争者。
