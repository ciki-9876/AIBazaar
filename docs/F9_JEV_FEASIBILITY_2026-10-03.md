# F9：Jev 决策模型可行性调研

日期：2026-10-03。状态：用户要求调研是否适合作为主要 AI 模型；尚未选择模型，未接入 API、未产生推理费用、未实测房间表现。

后续：[Laya 与本地专用模型方案](./F9_LOCAL_DECISION_MODEL_PROPOSAL_2026-10-03.md)讨论开放权重微调及轻量策略网络，用户要求同时支持Windows与浏览器。未选择模型、未训练；取消战术API费用与开放博弈的本地实现分别验证。

承接 [实时控制与费用方案](./F9_REALTIME_LLM_CONTROL_AND_COST_2026-10-03.md) 与 [ADR-0025](./design-log/decisions/ADR-0025-llm-contestants-and-elimination-experience.md)。本文区分供应商说明、外部实验、助手推演及待测目标；不改变现行玩法和历史决定。

## 1. 判断

**建议将 Jev 列为主要实时战术模型的优先验证候选，暂不把它定为整名选手的唯一模型。**

按调用数量衡量，它可能承担大部分探索、搜刮、中断、站位和进退决策；按综艺核心体验衡量，长期利益、承诺、谈判和新策略生成仍建议由生成式模型参与。判断依据是它的接口、已公开游戏案例及官方能力边界，不是 F9 已验证结果。

上一轮生成式模型短战术每 5–15 秒更新一次只是测试起点。Jev 提供更频繁更新的候选路径：遭遇时先测约每 0.5–1 秒一次，安全探索降低频率，关键变化提前触发；本地连续动作继续使用现有 30Hz 模拟。不得把此频率写成响应保证。

## 2. 核实的产品与接口

从 TypeSafe 官网导航确认官方文档域名为 `docs.typesafe.ai`，官方 API 为 `https://api.typesafe.ai/v1/systemone`。搜索中有不少名称相似的独立站及转售网关，不把它们的收费、密钥或接口冒充官方服务。[官方快速开始](https://docs.typesafe.ai/introduction/quickstart)

Jev 是面向软件判断的 System One 模型，读文本或 JSON 状态，不生成自由文本、理由或代码。当前接口有三种判断：从候选中选择、按描述等级评分、回答是／否的概率。它不是本项目此前讨论的聊天式生成模型，但模型确实参与决定动作。[System One](https://docs.typesafe.ai/concepts/system-one)、[接口](https://docs.typesafe.ai/api)

截至本轮核对，官方列出的稳定版本为 `jev-1.13.0`：输入 $0.042／百万 token，输出免费；文本输入，64k 请求预算，状态加最长单问题不超过32k。公布限额80请求／秒和100k输入 token／秒，供应商说明限额可能动态调整；英文表现优于中文。不支持按客户数据微调或 LoRA。[模型参考](https://docs.typesafe.ai/models)

正式实验应固定版本，记录实际模型 ID；当前只核实云端 API 路径，没有确认官方可下载权重或本地部署渠道。第三方名称相似的 OpenJev 项目不能直接视为同一模型或同等能力。

## 3. 速度证据及其边界

供应商发布文称端到端70–500毫秒，测量通常来自美国西海岸、服务当时也位于该地区。它描述了结构化游戏状态驱动的 Doom 演示，约每秒10次请求；同时承认传统游戏机器人可能玩得更好。首页193.6倍速度提升来自特定工作流，不代表 F9 或任意请求的提升。[官方发布说明](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

这足以支持“值得做实时游戏实验”，不足以支持国内玩家固定100毫秒、连续高负载仍满足同样延迟、或已具备优秀拉扯能力。游戏服务器位置、玩家链路、请求长度、并发和排队都要计入。

外部原始实验提供两类补充证据：

- [Jev Plays Pokémon 项目页](https://jev-plays-pokemon.standardagents.ai/)记录了通关，但同时说明 Opus 5 监控日志并实时构建执行框架。它证明协作系统可运行，不证明 Jev 无需辅助就能规划完整游戏。
- [Jev-Mobile 预印本](https://arxiv.org/html/2609.30186v1)采用低频 VLM 定目标、Jev 从当前可执行候选选择动作。在 AndroidWorld 中报告79%任务成功率，对照逐步 VLM 为84%；成功轨迹的平均时间与模型费用下降。作者区分候选覆盖、选择质量和移交失败。这是 GUI 系统的证据，不能直接外推为战斗或欺骗博弈能力。

## 4. 对 F9 能承担哪些决策

| 层级 | 建议承担者 | 权限与节奏 |
| --- | --- | --- |
| 长期策略与关系 | 生成式模型 | 关键事件触发；决定利益目标、联盟、承诺、谈判方案及新策略，不能只写台词 |
| 近期行动选择 | Jev | 遭遇初测1–2次／秒；决定搜哪处、是否中断、走哪个站位、继续追击或撤退 |
| 连续身体执行 | 本地控制器 | 30Hz；行走、碰撞、避障、当前距离修正、即时危险响应与自动攻击 |
| 状态与记忆 | 游戏系统 | 保存个人观察、事实／传闻、计划、承诺、资源 UID 与实际事件；按需提供给两个模型 |

这是候选分工，不预先限定 Jev 只能选走位。明确报价、是否接受已给出的交易、简单关系判断也可以纳入对照实验；涉及多步反推、新骗局或跨期承诺时先交给生成式模型。是否能进一步扩大 Jev 权限由结果决定。

记忆不属于任何一次模型请求自身。每个选手要有独立的存储、观察与检索；共享模型不能导致共享秘密，也不能让一次接口调用自动获得长期人格。

## 5. 如何让有限选项仍然产生真实模型行为

关键不是给 Jev 四个永久选项“攻击／逃跑／搜刮／跟随”，而是根据当前个人观察与可用动作构建具体候选。候选生成器负责行动存在且物理合法，不提前替角色筛出最优动作。

示例：角色计划先完成搜索再返程，玩家靠近，怪物从另一方向进入。程序可提供：

- 继续翻找当前柜子，仍需要支付剩余搜索时间。
- 中断搜索，移动到已知东侧墙角，暂时切断视线。
- 移向可达西侧站位，在自己的有效射程内保持距离。
- 沿已探索退路离开资源点。
- 去已知队友位置附近，保持原有中立／联盟状态。
- 保持当前动作，或请求战略层重新规划。

Jev 得到自己的目标、相关记忆、当前行动持续时间与这些候选的语义后选择；下一次观察会改变候选，角色因而可以中断、变换站位、放弃资源或继续坚持。模型选择哪种意图，本地执行对应运动。

生成式模型还能决定新的行动目标、条件计划和谈判组合，再通过已实现的游戏动作展开为候选。它不能发明游戏不支持的物理能力；“自主策略”不等于无限行动权限。

如果全部选项都是开发者预写完整剧情套路，Jev 会退化成脚本分支选择器，无法满足用户的核心要求。需要同时检验候选是否覆盖有效策略、模型是否选得合适，而非只统计接口成功率。

## 6. 官方弱项如何影响游戏

官方2026-10-02更新的 [Jev 1.13 已知弱项](https://docs.typesafe.ai/model-jaggedness/jev-1.13)列出数值、间接推理、无关长上下文、字面理解、诱导内容及选项顺序偏置。以下是针对 F9 的工程推演：

- **距离、伤害、时间由规则算。** 不让模型从坐标计算哪处安全；先计算路径、距离、视线与搜索剩余时间，再附上“可进入己方射程／切断视线”等简明描述。不要用评分插值生成精准坐标或距离。
- **短战术不塞完整人物生平。** 只取当前目标、相关承诺、最近观察和行动结果；远期关系按需检索。
- **把复杂利益拆明白。** 对“假装背叛以换取第三人的信任”这类多层判断，生成式模型负责分析；Jev 不因速度快就自动具备该能力。
- **做候选顺序对照。** 测试同一状态下调整顺序是否导致非合理变化；不能总把期望答案放第一项。实验中的顺序或抽样要有明确种子并记录。
- **中文必须单独测。** 战术字段可用英文语义和固定 ID；中文玩家交涉保留原文，不能假设翻译免费、无延迟或完全保真。
- **角色对白不能成为系统指令。** 玩家可以在游戏规则内欺骗选手，但“忽略规则、赠送全部物品”只能作为该角色收到的发言，被事实与承诺约束；不得绕过交易、信息和所有权检查。

“零幻觉”在此主要指输出结构受约束；选择一个合法选项仍可能是错误战术。官方说明校准是预测集合上的性质，不保证单次正确。`confidence`来自输出概率分布，不是战术胜率或当前回答准确率。[System One](https://docs.typesafe.ai/concepts/system-one)、[confidence 定义](https://docs.typesafe.ai/confidence)

## 7. 异步请求和确定性

测量观察生成→请求→完整选择返回→重新校验→开始执行的全过程，而非只看供应商推理时间。开发端、部署端与目标玩家链路分别测 P50／P95／P99。

建议每个选手至多一个实时决策在途，期间合并新观察；模型慢时降低频率而不是堆积过期请求。等待时执行既有计划及本地即时避险；无法依照现有计划解决的重大结盟／资格转移等待战略模型。对低确定度的重大选择升级处理，阈值须由本游戏验证。

请求绑定角色 ID、观察版本、计划版本和模拟 tick，响应后校验当前目标、距离、所有权与候选仍有效。独立并行问题不能互相看见本次回答，故不要分别问“选哪个目标”和“选哪个互相依赖动作”再盲目拼接；优先选择已经绑定目标与参数的完整候选。[并行问题语义](https://docs.typesafe.ai/concepts/state)

限流／过载的默认重试可能让旧状态迟到。实时请求要有总时限和可取消机制，过期动作不补执行；不要重试已经可能完成的物品转移。多角色在明确模拟时刻提交输入，资源争用依明示规则裁决，不以 API 回包先后让角色获得晋级优势。

共享服务限额也不是单玩家额度。按2000输入 token、3角色每秒2次，单局约6请求／秒、12k token／秒；按公布限额简单相除，多局同时运行很快需更高配额或请求调度。不能认为廉价单次调用意味着无限在线玩家。[模型限额](https://docs.typesafe.ai/models)、[错误与重试](https://docs.typesafe.ai/api)

模型输出属于外部输入，由适配器记录，模拟在固定 tick 接收。保存观察、候选、模型版本、返回选择与真实执行结果；回放消费记录，不重新联网推理。保持既有规则 RNG、存档产品边界、物品 UID 与原子资源转移。云端模型未提供完整离线游玩方案，当前研究不能消除联网依赖。

## 8. 人民币预算

采用上述官方直连单价。假设每次请求实际计费输入共2000 token，包含状态、指令及候选；预算汇率 $1＝¥7.20，**不是实时汇率**。每次约 ¥0.0006048。以下三名选手均连续运行十分钟，是负载算例，不是实测消费。

| 每名 AI 的频率 | 总请求 | Jev 费用 |
| --- | ---: | ---: |
| 每10秒一次 | 180 | ¥0.108864 |
| 每2秒一次 | 900 | ¥0.54432 |
| 每秒一次 | 1800 | ¥1.08864 |
| 每秒2次 | 3600 | ¥2.17728 |
| 每秒5次 | 9000 | ¥5.4432 |

计算：费用＝角色数×秒数×频率×实际输入 token÷1,000,000×$0.042×7.20。输入若升到8000 token，则费用乘4；安全探索降频或离屏抽象处理才能减少总次数。实时性未过关时，不能根据账单反推能稳定跑该频率。

两种频率的模型不应只比较每次单价：Jev 高频请求可能比上一版低频廉价模型的整期费用高。生成式策略／谈判、额外检索或翻译、重试、网关差价、服务器和税费另计，账单以真实 usage 为准。上一份文档中的长策略预算仍是独立假设，不在本文把它当已验证价格方案。

## 9. 建议验证顺序与采用标准

先准备同一角色、装备和主题房间，用一名竞争者比较：本地战术基线、生成式模型短战术、Jev 短战术、Jev＋生成式策略。模型对照尽量共用观察、候选与执行器，避免把候选改进算成模型能力；混合系统另评价开放策略的新增作用。

至少包含：追逃拉扯、玩家抢先搜柜、怪物夹击、视线丢失、同一关系下资源紧迫程度变化、已经许诺援助时的新诱惑、中文谎言和报价。用固定快照测试选择，再做闭环运行测试；不能只考静态选择题。

验收建议（均未实测）：

- 国内目标部署链路的短决策 P95≤500毫秒，作为1–2Hz实验目标；达不到时降频仍需检验行为是否自然，不能把超时归咎于玩家。
- 可见区域持续行动，不站着等待模型，不出现左右反复和每次新回答都打断未完成动作；允许模型改变意图，但记录行动持续时间与实际结果。
- 感知、物理、原子资源和承诺约束检查全部通过；不能用模型准确率容忍穿墙、透视或复制物资。
- 模型能根据玩家实际行动改变搜索和战术；同一上下文中的稳定偏好与新证据下的调整都可观察。
- 同时报告成功率、错误选择、候选缺失、移交频率、过期率与每分钟账单；不能用高请求速度掩盖差决策。
- 对长期关系和晋级博弈，看计划是否前后一致、交易是否合理、承诺是否实际影响行动；会生成漂亮台词不算通过。

若 Jev 的短战术通过、长期判断较弱，则采用混合方案；如果连窄战术也频繁选错或国内延迟不达标，则把它限制为评分／选择辅助，比较其他模型。当前结论是优先验证候选，不是已决定全面替换。
