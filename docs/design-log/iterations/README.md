# 设计迭代记录

这里记录一次有目标的设计变化：我们改变了什么，原本想验证什么，看到什么证据，以及下一步是什么。

## 现有迭代索引

- [F9](./F9/INDEX.md)：卡牌、实体、现场工作、回家到达和相关闭环。

## 迭代规则

- 一次迭代可以引用多个实现文档，但必须有一个清晰的体验问题。
- 先写假设和成功信号，再写改动；避免把“已经写出来”误认为“已经验证”。
- 记录正面和负面结果；未达到目标也是有效知识。
- 若结论改变稳定设计规则，额外建立 ADR 并更新设计 DNA。
