# 2026-09-25 · 战斗空间与可读性评审

## 用户反馈与已决定方向

- 用户认为当前材质与光影已经基本达到本阶段需要；下一轮重点转向玩家体验，不据此宣布全部资产完成。
- 当前战斗视角过平，需要提高俯视程度，方便观察棋盘。
- 三路屏障应移到各自核心前方、各自布阵区后方。由远到近为：敌方核心 → 敌方屏障 → 敌方装备 → 交火区 → 我方装备 → 我方屏障 → 我方核心。己方攻击不应穿过己方屏障。

这是空间表现修订，不改变三路屏障的规则、卡牌不可被击毁、宿主共用生命或确定性命中。此前屏障在双方装备之间的摆法由本记录取代；原实现和历史记录保留。

## 本轮观察事实

在独立 `/art/chamber` 新开测试页，实际检查 1280×720 桌面、开始战斗、17 秒暂停与卷簧弩详情。没有操作用户原有标签页的进度。

- `chamber.ts` 当前桌面镜头位置 `[0,4.8,6.9]`，目标 `[0,0,0]`，垂直 FOV 65°；相对水平面向下约 35°。远端装备明显小于近端装备。
- `scene.tsx` 装备深度为 ±1.78，屏障深度为 ±0.95，核心命中深度为 ±3.22；屏障确实位于交火区一侧。
- 桌面截图中可操作装备主要集中在中央偏窄的区域；顶灯、墙面与下方操作面板占据较大画幅。
- 默认装备名称在悬停/交战交互时呈现，核心主要以数字表达生命，六个屏障读数很小。冷却虽已存在，远端读起来仍吃力。
- 详情支持暂停、关闭恢复；这项能力应保留。详情位于右侧叠加，下一版扩大棋盘后需重新检查遮挡。
- 屏障已具备裂片和破裂标记，不是没有反馈；问题是路线整体暴露状态与受击结果的视觉优先级不足。

本轮为 Agent 定向体验评审，不是独立新玩家测试；未改渲染代码、玩法、数值或存档。

## 修改建议（提案，尚未实装）

1. 战斗/布阵共用稳定高位透视，先试相对水平面向下 55–60°、垂直 FOV 40–45°，同时调整距离和取景。数字是试调起点，不是已验证最佳值。保留进入房间的第一人称，坐定后明确转为读棋盘的机位，交火中不自动推拉。
2. 屏障移至装备后方，贴近连续核心但留有可读间隙；三段覆盖整个核心宽度。近侧屏障不得遮住我方装备。弹道、命中火花、破裂碎片、修复反馈、HUD 锚点必须一起迁移。
3. 装备使用低矮基座、统一可见占地与明确朝向，使经过敌方装备区的弹道在视觉上从其上方通过，不引入装备碰撞或破坏规则。
4. 装备和棋盘获得主要画幅；缩减底部操作面板，压低房间装饰的注意力，材质/性能工具收进调试模式。
5. 三路用低对比刻线和稳定对齐建立连续关系；悬停某装备时只强调关联路、屏障及作用对象。避免常驻铺满箭头。
6. 核心加紧凑可读生命条；屏障强化完好、受损、破裂三态。颜色以外同时使用形状、缺口和纹理，避免依赖敌我色差。
7. 装备保持可读名称与明显冷却；临近发动、实际发射、真实命中按现有事件分别表现，防止所有物件持续发光争夺注意力。
8. 命中分清屏障吸收、本体损伤和实际减伤，局部反馈配少量短数字；同时命中做合并。溢出伤害在同一结算事件下表现，不另加一段会改变结果的飞行时间。
9. 拖动突出完整占格、合法/非法落点与落地确认；详情固定在不遮棋盘的位置，悬停快速看、点击固定并暂停，拖动时关闭。
10. 核心的轮廓目前仍容易被读成桌面摆件；后续通过面向玩家的局部反应、破路后局部暴露、真实损伤后的持续状态改善主体感，优先级低于空间和信息改造。

## 建议实施顺序与验收

- P0：镜头、屏障位置、关联弹道/特效/HUD，以及棋盘可用画幅。
- P1：路线关联、生命/冷却/命中信息和拖放、详情的可读性。
- P2：核心状态演出与调试入口整理。

验收需检查：默认视角能同时看到双方九格与三路；远端装备能辨识；同路攻击不穿己方屏障且不汇聚到屏障中央；近侧屏障/核心不遮挡可操作区域；不打开日志也能指出哪路破裂、谁受到了本体伤害；布局改变不改变相同输入的模拟/回放结果。宽屏和窄窗都需重新截图验证，不能仅更换相机参数后宣布完成。
