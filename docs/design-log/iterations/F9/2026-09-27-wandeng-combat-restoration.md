# 归物师恢复 F9 战斗基线

日期：2026-09-27。决定：[ADR-0017](../../decisions/ADR-0017-wandeng-arena-baseline.md)。

## 事实与修正

此前故事原型仍使用原引擎，但接引/商店只抽八张牌、仅十二张有旧物表现数据、双方增幅器全为空；没有战前完整敌阵、状态详情、弹道联动、回放历史和完整复盘。共用引擎不等于玩法完成迁移，这是本轮纠正的设计认识。

| 原基线 | 本次归物师接入 |
| --- | --- |
| 50 卡 / 10 增幅器 | 50 卡完整数据、可检索图鉴、全卡池接引/商店；三路增幅器可免费整备，敌方实际配置 |
| 3 路 × 3 格、1/2/3 格物品、同名最多两张 | 保留原验证；点选和拖放、收回口袋、自动整理；失败动作原子回滚 |
| 战前看到敌阵 | 教学外的整备桌展示下一守关人，路边对决事件中也能查看并调整；预览与开战使用同一输入生成函数 |
| 布阵与联动 | 共用 `formationRelations` 和 `placementPreview`，显示真实关系与拒绝原因 |
| 战斗反馈 | 共用 `FlatTable`：双向弹道、实际命中数字、实际触发联系、灼烧/侵蚀、破屏、卡牌与增幅器状态 |
| 控制和复盘 | 暂停/继续、1/2/4 倍速、0.25 秒步进、时间轴、事件跳转、减少动态、详情暂停并恢复；共享逐卡、逐路、转折、明细与上一场比较 |
| 归档 | 最近 30 场完整输入；刷新保存、导入只读回放、文件/文本导出；回放不结算经济 |

叙事、赎回路费、不掉玩家卡、胜利取得真实敌方实例、终局统一送达仍按 ADR-0014。教学沿用引导中的小棋盘，实际对战与启程后整备进入完整桌面。

## 主要文件

- `lib/wandeng-game.ts`：完整卡池、增幅器、精确预览、历史输入、旧书签迁移、回放校验/序列化。
- `app/wandeng/wandeng-experience.tsx`：旅途整备、图鉴和对决手记入口。
- `app/wandeng/wandeng-cards.tsx`：复用原纸纹卡面；核心数值仍是可换行的类型色数字。
- `app/wandeng/wandeng-battle.tsx` 与两个 battle CSS：纸纹桌面、原版战斗组件接线、查看和复盘、回放。
- `app/arena/flat-table.tsx`、`arena-review.tsx`：新增可选卡面/名称适配参数；默认行为不变。
- `lib/wandeng-battle.test.mjs`：新增九项覆盖迁移、所有卡/增幅器、精确预览、回放和原子性。

没有修改 `arena-engine.ts`、`arena-catalog.ts` 或旧版天气/英雄规则，没有修改 `/survival`。

## 验证证据

- 206 项自动测试通过；lint、TypeScript 和生产构建通过。构建保留原有大包体积提示。
- 全 50 卡轮换 10 增幅器，存档重建后的结果与原引擎入口逐帧一致；新增测试不把这种等价性当作强度平衡证明。
- 旧对局无增幅器时仍保留原输入；旧打开商店的选项不被完整池覆盖；移动、无效增幅器、失败购买等不会部分消耗。
- 原有三 BOSS 到送达、战败赎回与负债测试保持通过。
- 实际浏览器走通序章、教学、来信启程、三路增幅器配置、50 张图鉴与机制检索、三次修缮、首 BOSS 胜利与真实掉落；结算后为 28 路费，回放没有重复奖励。
- 查看详情暂停、关闭恢复；键盘时间轴至 0.25 秒、事件跳至 10.25 秒；三路实际承伤/修屏统计、历史刷新、文本导出/错误拒绝/重新导入可用。
- 检查桌面和窄屏（请求 390px 视口）布局；窄屏棋盘在自身容器横向滚动，不撑大页面。实际完成“收回座钟、放音乐盒、再恢复座钟”的操作。

## 仍需验证

- 完整池与新增敌方增幅器进入旅途后，获取频率、成长经济、敌阵强度尚未做系统平衡。
- 50 个机制沿用原定义，画面目前复用 12 张旧物临时插画；不是 50 张最终独立美术。
- 内置浏览器文件下载事件没有得到自动化确认，因此提供并实际验证文本导入导出兜底。全屏按钮沿用浏览器能力，并提供失败提示；未将本机未确认的全屏结果计作通过。
- 这仍是序章与三程切片；完整 60–90 分钟长局和局外成长不属于此次战斗恢复。

## 后续用户灵感

用户在修复期间提出：通关一局解锁自由模式、上传图案、AI 生成名称/文本/技能，并控制自制牌强度。要求先完成此次修复再脑暴，尚未要求实现。见 [自制旧物构想](../../../F9_WANDENG_CUSTOM_CARDS_BRAINSTORM_2026-09-27.md)；其中平衡模型和产品流程均为待讨论方案。
