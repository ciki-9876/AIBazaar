# 2026-10-04：电梯完整非AI赛季实施与验收

## 请求、决定与范围

用户在完整流程SPEC后授权：除AI以外按SPEC完成全部开发，并用浏览器自测验收。本轮采用[ADR-0039](../../decisions/ADR-0039-elevator-complete-season-with-finite-rescue.md)的有限库存救援、稳定金票配额与终局兑换方案，完成规则到100F，而非仅做到11F切片。[执行规格](../../../F9_ELEVATOR_FULL_FLOW_IMPLEMENTATION_2026-10-04.md)明确数字和当前边界。原草案、0033和旧季规则保持历史原义。

没有改动AI实验或卡牌规则，没有提交、发布或创建PR。工作树原有大量项目拆分和卡牌修改，与本轮电梯变更分开看待。

## 浏览器实际操作

本地电梯服务`http://localhost:4173/`。使用真实界面、鼠标、键盘和可见GM阶段进行操作，没有在浏览器注入内部状态或跳过行为。GM用于准备案例，不代表AI自主到达或玩家手打完整100层。

| 案例 | 观察结果 |
| --- | --- |
| 第三层通关→结算→4F | 首票登记，4F扣一张进入。集结中名册对应12人，现场有玩家及11个参赛者实体。 |
| 准备层走动与广播 | 点击地面可移动；精力／食水保持100，无攻击和掉落搜刮。小地图全场可见。广播每次只显示标题、一行解释和段数。 |
| 保存广播与登梯开赛 | 恢复保存进度，广播结束后返程；选择5F资格通行开赛，普通票为0，开赛状态初始化。 |
| 有限普通票源 | 点击登记后持续交互，取得1张普通票，入口消失，无反复领取。 |
| 两张金票返程 | 撤离被阻拦，行囊真实有两张；扔下其中一张后HUD余一张，地面出现手动拾取入口，不自动捡回。 |
| 金票合法兑换 | 走回电梯自动兑换10F资格，实体票从背包移除；只有10F重进和11F资格通行，10→11不减普通票，不能直接跳12F。 |
| 20F前点未结算 | HUD显示“名册待结算”，没有新金票。 |
| 真实仓库预留 | 六个实物锁定其中三件，格数不减少；预留物不能转移／销毁。 |
| 休息与救援 | 休息从精力70增长到71，同时食水减少。精力归零的救援消耗六件库存中的三件，恢复45；背包留地，装备和保险格保留，食水继续消耗。 |
| 永久死亡与新季 | 无储备时显示永久死亡；没有免费满状态返程。新季重新开始教学、立即替换旧季进度，不继承物资。 |
| 显式攻击与取消 | 未选择时对手精力100；点击攻击后降至87；停止后保持87。测试对手为明确GM实体，没有AI策略宣称。 |
| 100F终局 | 到达与手动拾取都不显示胜利。鼠标沿地面实际移动到电梯，再点击返程；合法带回后显示“本季优胜”。事件回看含取得／资格／优胜。 |
| 正赛仓库投喂 | 两份精良脑浆只消费一份，40／40；零件逐件投入1／2、2／2后升Lv.3，跨度5、仓库32，盈余脑浆仍在仓库。 |
| 终端暂停 | 操作仓库及窄屏检查期间，精力／食水仍为70／60／60，没有菜单内资源损耗。 |
| 暂停与刷新恢复 | 暂停时广播1／6、4F、资源100／100／100；等待后仍相同。刷新、继续旅程后恢复同一段和资源，没有补算离线时间。 |
| 手机宽度 | 390×844视口实测文档宽390、界面元素无横向溢出；首页可竖向滚动。临时视口覆盖已复原。 |

## 自动化证据

`survival-season.test.mjs`检查首票唯一、开赛门槛、无资格倒计时、有限票原子失败、N=6／X=2固定四票、晚到与死亡不改配额、多票阻门、单次资格、掉地／死亡不复制、前点结算后才能冻结下一点、最后一人终局、真实救援锁定和手动扔下。

`survival-season-session.test.mjs`有15项集成测试：第三层失败不可开季；点击交互中断／部分存档；逐层执行5→100与全部10个据点；真实4F自由行走／广播／共同开赛；同层有限持久与低层关闭；两票物理门禁与10→11；实际终局手动拾取及返程；有限救援与永久遗物；连续两套库存救援后第三次死亡；持多张金票救援后的公共可达落点；仓库分次投喂；电梯／旅途／休息代谢；显式PvP；所有95个目的地可达性／3:2面积；全部GM和损坏存档拒绝。

全百层路线测试固定角色位置并关闭战斗以隔离规则；票、取物、消耗、资格和存档使用实际执行器，食水仍随模拟消耗，不伪造免费补给。最终保存少于1MB。另有既有黄金回放和存档兼容测试，未重生黄金fixture来消除失败。

最终检查：`npm test`全仓435／435通过；`npm run lint`、`npm run typecheck`、`npm run typecheck:elevator`通过；电梯正式构建通过，预渲染3条路由；`check:boundaries`、`check:determinism`和`check:dependencies`通过。现有vinext的动态导入拆分提示不影响构建。没有更改黄金回放fixture，没有为本轮改变其他产品规则。

关键界面事件与规则证据均来自执行状态，未把平衡假设写成测试结论。

## 待验证体验

有限资源是否足以支持各阶段路线、名册冻结等待是否公平、先到优势与囤票压力、可救援次数与整季时长仍需真人及AI接入后试玩。房间为模块复用，未制作100套独立关卡。暂停／资源时序按固定tick成立，后台浏览器帧率不作为正式性能验收。

失焦和隐藏页事件已经接入同一个整季暂停入口。尝试在验收浏览器切换第二个本地页，未触发真实窗口失焦；当前工具的焦点模拟不能替代系统切换应用测试，因此不把此尝试记录为失焦验收通过。菜单暂停、页面刷新和无墙钟补算已有独立证据，真实系统失焦需在正常浏览器另行复核。
