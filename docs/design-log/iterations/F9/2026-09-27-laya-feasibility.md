# Laya 玩法组件可行性研究

日期：2026-09-27。状态：研究完成，方案待验证，未实装。

## 用户目标

研究开源 Laya 是否能引入 F9，成为玩法引擎的一部分。用户未指定优先应用场景，也未要求本轮安装或接入模型。

## 事实与证据

- 核查上游代码、模型页、评测与 F9 当前实现，完整来源和版本见[研究报告](../../../F9_LAYA_FEASIBILITY_2026-09-27.md)。
- Laya 对文本执行有限选项选择、等级评分和是否判断；没有图像理解或自由生成文字能力。
- 上游提供 Python 和 TypeScript/ONNX 路径；浏览器适配与本机性能未测。
- 上游中文诊断存在高置信度误判，不足以将模型当成可靠规则裁判。
- F9 已有确定性模拟、校验和候选反制搜索；自制技能仍是设计提案，不是已实现的通用能力。

## 建议与假设

**建议，非已接受决定**：先验证“物品记忆 → 合法机制方向推荐 → 玩家确认 → 冻结蓝图”的低频语义环节。模型不直接决定强度、扣资源、结算或修改已公开敌阵。

**H1，待验证**：理解玩家自己的旧物经历，比单纯手选模板更能建立所有感与同行意愿。

**H2，待验证**：少量明确候选、领域校准和规则兜底能够让中文推荐在实际设备上达到可用水平。

## 不采用的本轮方案

不建议替换战斗核心、让模型自由执行技能或逐帧推理。仅保存 AI 结果可保证既有回放复现，不能自动保证跨设备同 seed 新局一致；需以冻结内容/玩家确认后的命令作为规则核心的输入。

这是研究建议，不是永久否定相关实验；也不改写 A-01、A-07、A-08 或现有自制卡脑暴。

## 验证边界与下一步

未下载权重、未运行推理、未微调、未测 F9 准确率或玩法体验。只新增研究文档，无玩法代码变化。

下一步建议是独立中文方向评估，与手选和规则基线对照，再判断是否值得接入；具体样本量、候选数量和采用门槛见报告，均为实验建议。
