## 体验问题

- 毒和火什么都打得过，资格赛前整备巡演箱没有意义。
- 花色不影响战术。
- 新玩家进入第一场对决时，没有逐步说明。
- 文案偏说明书。

## 假设

把花色锁定为状态，再用机制连成克制环，「读对手 → 换道具」就会成为每场比赛的决定。第一章的资格赛设计成「需要克制才能稳赢」，就能把这个循环教给新玩家。

成功信号：

- 每条声明的克制在自动对局中 ≥ 60%。
- 六套的均值都在 35–65% 之间。
- 第一章可以在不读规则页的情况下通关。

## 改动

**玩家能感到的变化**：

- 出 ♠ 竖盾、出 ♥ 回血、出 ♣ 下毒、出 ♦ 点火。
- 状态之间有清楚的克制：
  - 火落在盾上会被闷熄。
  - 着火时治疗打折，出手烫手。
  - 毒穿盾，攒牌越多毒发越重。
  - 回血会洗掉毒。
- 快甩单张削盾，大牌型造成重创，压轴一手能吹灭身上的火。
- 六套卡组的标签上直接写着「克 …」。
- 第一课一步一步教选牌、出手、读对手、整理和框选，等玩家操作时时钟停住。
- 米娅给出对手情报和护盾道具；布阵界面顶部显示她的建议。
- 全部对白、道具俏皮话、结果页和规则页都改成英式幽默语气。

## 结果

### 已确认事实

- `npm run test:throw:cards`：76/76 通过，包括平衡回归测试。
- `npm run check:boundaries`、`npm run check:determinism`：通过。
- 类型检查：用最小 React 类型垫片对 `apps/throw/src` 做 tsc。剩余 9 条报错都来自垫片本身（`useState()` 无参重载，以及内联事件参数推断），新代码没有类型错误。

### 观察与证据

**v3 基线**（每组对局 12 个种子，对称化）：

| 卡组 | 均值 |
|---|---|
| 青苔 | 92% |
| 余烬 | 85% |
| 成长 | 71% |
| 护灯 | 48% |
| 对子 | 45% |
| 回甘 | 39% |
| 星光 | 34% |
| 快甩 | 22% |
| 止雨 | 13% |

**v4 最终**（每组对局 200 个种子，对称化）：

| 卡组 | 均值 |
|---|---|
| 星光 | 54% |
| 青苔 | 53% |
| 余烬 | 52% |
| 护灯 | 52% |
| 快甩 | 47% |
| 回甘 | 42% |

11 条声明的克制全部成立，在 75–91% 之间。平均每局 58 秒。

**v4 调参过程**（共 17 轮矩阵，每一轮都先用诊断脚本定位原因，再改）：

| 现象 | 处理 |
|---|---|
| 护灯 AI 太被动 | 放宽出手条件 |
| 星光 AI 太慢 | 放宽成型条件 |
| 回声针盒惩罚快甩 | 改为只在被 ≥3 张命中时触发 |
| 护盾产量不足 | 上调补丁旧伞、守灯小毯 |
| 闷火太弱 | 加入「火落在盾上减半」 |
| 毒永存太强 | 加入每 2 秒退一层 |
| 换调风铃的数值非常敏感 | 取中间值 |

**浏览器走查**（Playwright + Chromium，esbuild 打包同一份源码）：

- 第一课 8 步顺序正确，冻结期间 tick 不变，排序与框选两步能完成。
- 练习场布阵界面显示「克 …」标签和俏皮话；规则弹窗显示克制说明。

**走查中发现并修正**：

- 导师对白说送的是「催信闹钟」，实际送的是清露药包。已改对白。
- 状态悬浮说明仍是 v3 的规则。已更新。
- 抖擞披风的标签「抖毒」不通顺，改为「解毒」。

### 未解决问题

- 回甘续航均值 42%，最弱；被星光蓄爆克到 11%，可能是重创 5 秒过重。
- 代理脚本与真人差距未知。
- 跨流派混搭没有扫描。
- 项目原生的 vinext 构建、oxlint 与 knip 在本沙箱无法安装依赖，没有运行。

## 结论

接受 v4 作为当前规则基线。等真人试玩后，再决定是否修正回甘续航和重创时长。
