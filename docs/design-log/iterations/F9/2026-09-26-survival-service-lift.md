# 2026-09-26：移动维修电梯美术实装

后续决定：本记录保留当时实现。用户随后要求现实小轿厢开局，营地改为后期扩容候选，见 [ADR-0010](../../decisions/ADR-0010-human-scale-lift-and-camera.md) 及[新实装](./2026-09-26-survival-passenger-lift.md)。

## 用户决定

用户明确授权开始电梯美术迭代，并再次强调必须与房间内艺术风格一致。本轮将[上一轮设计提案](../../../art/F9_ELEVATOR_REBUILD_PROPOSAL_2026-09-26.md)推进到独立 `/survival` 实机；不修改该提案产生时的历史状态，也不替换旧冒险首页。

## 已实现

- 电梯与水处理站共用同一套青绿、象牙、暗红、黄铜色材质及手绘磨损、四段明暗和墨色轮廓。门外机械保持原有外观，舱内以暖灯和生活物品产生区别。
- 约 6.9×6.8 米钢板舱体：厚门框、双扇滑门与门袋、楼层调度屏、保管匣和货架、工具工作台、红毯折叠床、水罐、压力表与检修管道。屋顶剖切，近侧与两侧墙降低，中央留出通道。
- 家具、舱壁与门袋使用固定碰撞；模型与碰撞从共享布局取值。世界生成版本升到 3，种子组合方式不变；当次世界仍完整序列化。
- 准备出发时镜头拉近、略偏侧展示舱内；运行时平滑回到原战斗镜头。窄窗口将出勤文字放到下方。
- 门口 12 段灯显示实际撤离进度。战斗和读条期间门保持完全打开，移动或受伤仍打断撤离；成功后门才合拢。门的渲染不反向决定伤害、撤离或安全。

## 设计边界与假设

这轮实现的是美术和与之匹配的空间。床、工具台、保管匣等尚未接入睡眠、生产、仓储或设施专属交互；现有背包仍由 B 打开。不自动给予无敌或回血，不增加跨局保存。

对应 A-08：镜头与门状态应帮助识别玩家处境，不能在撤离尚未成功时表现为封闭安全空间。对应 MC-03：通过同风格的熟悉设施和暖色灯光表达返回感；该体验能否成立仍待用户验收，不能用截图证明。

## 验证

- 规则回归检查包含家具不能穿越、中央通道贯通、出门拿线圈、返回原位并成功撤离，保留装备身份。
- 所有资源／刷怪点在 16 个种子上的连通性、确定性模拟、迷雾及背包已有回归继续通过。
- 浏览器已检查桌面与 640×900 窄窗口，完成出门拾取线圈、点击地板返回、触发撤离并保留 42 价值装备的流程；成功结算中可见双扇门关闭，浏览器错误日志为空。
- `npm test` 175 项通过；`npm run lint`、TypeScript 检查与生产构建通过。构建保留已有大分块提示，尚未进行专门低端设备性能测试。
- 截图位于 `outputs/survival-lift/desktop.png`、`narrow.png`、`in-room.png`、`extracted.png`。这些证明实机外观和流程连通，不代替用户对美术或平衡的验收。
