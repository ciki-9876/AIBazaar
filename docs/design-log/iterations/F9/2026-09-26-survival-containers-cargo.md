# 2026-09-26：容器搜刮、二维背包与电梯美术提案

## 用户事实与决定

用户认可手绘工业版，要求箱柜长搜索、多件物资、真正格子管理；电梯先交设计方案。接受的方向与本轮实验数值见 [ADR-0009](../../decisions/ADR-0009-survival-containers-cargo.md)。本轮没有改变十格装备相邻、持续敌群、失败损失和单机定位。

## 已实现事实

- 地面散件、设备箱、补给柜分别需要 0.8／3／5 秒停留；低精力延长。箱柜开启后留下模型，物资逐件按合法空间转移，剩余物资保留原身份。
- 普通运输包变为 4×2 格，具备多格占位、拖放、点选放置、两格旋转与自动整理。单格安全容器和十格装备栏仍独立；跨区转移保持原身份，失败动作不部分改变状态。
- 电梯方案已交付为概念图和布局文档；实际电梯仍为本轮以前的模型。

## 验证证据

- 规则自动测试覆盖 4×2 几何、非法移动原子性、碎片空间阻止卸下、3+3+2 格自动整理、箱柜时长、移动中断、低精力延长、一次多件与满包残留。
- 浏览器已完成设备箱翻找，确认一次取得锯环、机械零件与口粮；装备自动装入十格栏，普通物资进入二维包。已验证钉枪卸入背包并旋转纵向占两格。
- 浏览器确认口粮可拖到第八格，机械零件可点选移到第五格，钉枪可纵向放置，物资可转入独立安全容器；完整八格与操作区在桌面弹窗中可见。另一次开局确认补给柜一次取得三格物资并保留开启模型。
- `npm test` 174 项通过；`npm run lint`、TypeScript 检查和生产构建通过。构建仍提示已有较大资源块；功能通过不等于已完成大规模性能优化。
- 实机背包截图：`outputs/survival-room/cargo-grid-refined.png`。以上验证证明交互连通、空间与物品转移正确，不证明停留时长或容量已经平衡。

## 假设与未完成范围

长停留、多物资是否形成好玩的搜刮风险仍需用户体验；容器掉落表暂定。普通包只有八格，较大装备需要舍弃、旋转或重排。暂停整理、自动补给以及固定资源是否导致过低压力尚未平衡。

电梯“移动维修营地”只是推荐方向，床铺、储物、工作台的后续功能不能由概念图自动变成规则。没有新增局外仓库、跨局存档、楼层循环或 AI 竞争者。
