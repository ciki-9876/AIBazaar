# 2026-10-03：共鸣线对战 demo 实装

## 决定、范围与入口

用户认可节奏线细化方向，明确补充「每轮首扫卡牌立即触发并重置冷却」，要求开发。见[ADR-0030](../../decisions/ADR-0030-wandeng-rhythm-first-entry-demo.md)。这是一次允许改变战斗规则的新实验，承接[此前提案](./2026-10-03-wandeng-rhythm-scan-proposal.md)，并保留旧版训练场用于对比。

入口：`/wandeng/rhythm`，万灯城首页及原训练场均有「共鸣线试演」链接。沿用温馨精细像素素材、奶油纸与低亮桌面。双方九格卡牌上下排列，心灯和生命位于中间，战斗和结算均在一屏内显示。

本轮实现独立组牌／对战／复盘循环。没有新增旅途事件、局外收藏、成长经济、AI生卡或终局送达流程；没有迁移旧50卡、六牌、原回放或旅途保存。

## 执行规则（rhythm-scan-v1）

| 项目 | 执行口径 | 来源与状态 |
| --- | --- | --- |
| 容量与尺寸 | 每方九格，卡连续占1/2/3格，同名最多两件；空格保留旅行时间，首尾不相邻 | 承接批准方向；同名限制为原型参数 |
| 扫描 | 左到右连续移动，右端回卷；双方同速同相位 | 已实装，无三路／护幕 |
| 首扫 | 每圈首次进入一个卡牌实例，立即发动并重置本方线的触发冷却 | 用户明确要求 |
| 重复发动 | 留在该卡期间，线的冷却到期再发动；进入新卡与到期重合只发动一次 | 已实装；没有每卡独立秒表 |
| 默认时长 | 一圈9秒、触发间隔1秒、生命300、最长90秒 | 首版调校值，非平衡认证 |
| 两方结算 | 同一逻辑步读取旧状态，选各自当前发动，准备伤害／治疗／支援，再一起更新两方生命；双零平局，超时平局 | 避免动画顺序决定先手 |
| 强化 | 接下来两次实际攻击消费；同类取较高值并刷新次数，准备动作不消费 | 没有独立增益到期秒表 |
| 防护 | 下一次实际承伤批次按百分比减伤；同类取较高值，使用后清除 | 只有生命，没有新增护盾血条 |
| 支援 | 火柴只支援物理紧贴的攻击伙伴，每件每次至多一次；并入主动作，保留真实UID，不重新发起完整技能 | 非递归因果 |
| 储能 | 同一逻辑步的直伤、毒火合为一次实际承伤批次；手炉每批次存4，上限40，后续发动使用 | 防止弹道数量制造额外储能 |
| 灼烧 | 公共1秒拍按已有层数伤害，然后减1；最高30层 | 助手原型公式 |
| 毒 | 公共1秒拍按已有层数伤害，每3秒减1；最高20层 | 助手原型公式 |
| 新状态 | 不在刚附加的同一个公共拍跳伤；己方清除先影响原有状态跳伤 | 已实装并有测试 |
| 吸取 | 茶壶按实际直伤的一半治疗，过量攻击不生成额外治疗；治疗与同一步承伤共同结算，不能超过生命上限 | 已实装 |

逻辑以25毫秒固定tick推进，输入明确给出seed、时长、扫描周期、触发间隔、双方卡实例与生命。扫描边界由tick确定，视觉平滑插值不决定出手。当前技能无随机行为，seed为回放输入的一部分；没有从实时钟或环境随机数取值。

速度与触发间隔可以分别调整。每圈发动数量取决于各卡停留时间与间隔，不再固定为九次。更慢的扫描会使大卡多次出手；小卡至少一次。界面显示「每圈约N次」，具体执行以回放中的动作记录为准。

## 界面与回放

- 战前可换双方预设，分别调整扫描时长／触发间隔，选择物品放入空格，移除、左右交换；不同尺寸交换保持实例UID。支持向空格拖放，失败操作不消耗或部分改动卡牌。
- 对战聚焦当前扫描卡、下一张卡、冷却和两盏心灯。底部彩色粗体数值保留多效果容纳能力，图标在数字后作低对比提示。规则与故事放到暂停查看窗口，避免全文占用战中注意力。
- 放映机展示装片／聚光状态，手炉展示暖意；支援并入当前动作和心灯反馈。查看卡牌自动暂停，关闭后恢复先前播放状态。
- 支持暂停、0.5／1／2倍播放、时间轴、跳到下一次实际发动、看结果与逐卡发动／直伤／治疗／支援统计。统计直伤不包含毒火后续归因，不能冒充完整伤害贡献排行榜。
- 回放为输入JSON：`product=wandeng-cards`、`kind=rhythm-replay`、`schemaVersion=1`、`rulesVersion=rhythm-scan-v1`；重新模拟得到相同动作与帧。可导出、粘贴或读文件导入；未知字段、越界位置、重复UID、跨产品、未支持版本被拒绝，失败导入不替换当前对局。
- 390像素宽度下战前侧栏折叠为「调整」面板，选卡也可打开；对战仍完整显示上下双方。尊重减少动态设置。当前没有触控原生拖放验证，以点选放入和左右交换作为可用路径。

## 验证事实

- `lib/cards/rhythm.test.mjs`：12项通过。覆盖16组扫描速度／冷却组合下的每圈首扫、重置及重合不双发、空格、大卡重复、分段、同时致命、支援来源、状态、储能、防护、吸取、原子编辑、严格回放与双方交换对称性。
- `npm run test:cards`：99项通过；最终 `npm test`：343项通过，旧黄金回放保留。
- 卡牌专项typecheck、lint与build通过；最终全项目typecheck、lint及双产品build通过，电梯3条、卡牌9条路由，卡牌发布清单包含新入口。边界检查、确定性检查通过。
- 验证过程中曾遇到并行修改的 `lib/survival-gm.ts:464`（warehouse可能为undefined）；该处随后由电梯方向修复，本轮没有改电梯代码，最终重查通过。构建保留工具链已有的动态导入等警告，无构建错误。
- 浏览器实测1920×1080、1366×768、390×844：卡、心灯、播放控制在视口内，页面没有横纵溢出，主图等比。1280×720的结算统计也在一屏内。
- 浏览器操作验证：调整参数、不同尺寸交换、清空后重加卡、非法越界不修改、错误产品回放拒绝／正确回放恢复、移动端调整面板、查看后恢复播放、结算。实际文件下载及拖放手势未列入浏览器证据。
- 截图：`outputs/wandeng-qa/rhythm-battle-1920.png`、`rhythm-battle-mobile.png`；视口数据：`rhythm-viewport-checks.json`。截图证明布局与表现，不能证明用户的注意力和乐趣。

## 开发落点与后续风险

规则和目录：`lib/cards/rhythm.ts`、`rhythm-catalog.ts`、`rhythm.test.mjs`。界面：`app/wandeng/rhythm/`。产品路由：`apps/cards/app/wandeng/rhythm/page.tsx`及`scripts/products.mjs`。旧首页／训练场只新增实验入口，本轮不改其战斗规则。

体验未验收。优先观察玩家能否预告放映机的投射、理解手炉强化来源、看完一圈后主动重排。首扫保底可能放大小卡密排，速度与间隔的收益可能不均匀；数字要以整圈收益而非单次伤害评估。反向、停留、变速卡与回响尚未实装，也未把全池、旅途或通用生成卡框架迁移到共鸣版。
