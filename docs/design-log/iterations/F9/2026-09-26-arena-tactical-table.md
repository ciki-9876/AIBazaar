# F9 对战博弈：统一战术桌、状态、联动与复盘

日期：2026-09-26。用户已接受本轮主线，授权实装及直接发布。

承接：[效果描述与布阵可读性](2026-09-26-arena-readable-effects.md)、[独立对战博弈](2026-09-25-arena-duel-lab.md)。

## 已接受的设计决定

- MC-01 在实验场采用“同一桌面布阵 → 自动交锋 → 按事件回看 → 保留阵容调整再战”的完整闭环。布阵、观察、回看共享空间位置与装备身份。
- 宿主生命在双方各自的跨路生命条显示；每路单独呈现屏障、持续状态和增幅器。破屏、拆解停用、条件未满足、一次效果已触发应区别表达。
- 信息分为常驻局势、贴近装备的运转状态、按需展开的原因与细则。即时反馈用短句；事件明细保留来源、目标、实际变化与时间。
- 组合关系分为布阵关系预览和实际触发记录；联动连线只在查看或真实触发时出现。
- 复盘提供关键转折、三路实际收益、逐卡运转、效果明细、父局对照。事实对照不自动生成未经验证的因果或强度结论。
- 复用当前三路与确定性结算。演出跟随既有帧，镜头、动效设置和全屏不参与模拟；胜负已结算后允许现有 1.4 秒视觉收尾。

## 当前实装事实

- `/arena` 的第二套独立布阵图已由 3D 桌面上的直接操作取代。支持从卡库拖入、点击放置、移动、移回卡库；跨路占格、重叠和数量限制仍使用既有验证，移动保留 UID 与成长数据。
- 战斗收起武装库。双方所有装备均可查看；固定详情暂停，关闭恢复此前播放状态。提供全屏、简洁／详细反馈、减少动态、逐帧前进、时间轴和事件跳转。
- 显示灼烧／侵蚀层数、弹药与待装填、冻结／疾速／迟滞、储能、成长、升阶、工序、过载、再生及节拍。增幅器显示运转、停用、破屏失效、储能、触发或待机状态。
- 在既有引擎中增加只读观测字段：装备内部状态快照、增幅器状态、实际被动触发联系。没有调整伤害、数值、目标、冷却推进或事件排序。旧版 v1 档案仍保存完整输入，新信息由同一输入重建。
- 所有 50 张实验牌具有按机制族构造的实体几何，使用稳定的命名变种细节，修复临时映射为空的物件。10 种增幅器有屏障旁实体模块和状态灯。这是可读性用的程序化物件，尚非 50 件独立精制资产。
- 复盘以实际屏障吸收、宿主损失、有效修复等统计。灼烧与侵蚀持续伤害归于路线；再生汇总于宿主。逐卡统计不把聚合持续伤害全部归给最后一次施加者。控制统计成功施加次数，充能统计实际注入进度，不冒充节省的墙钟时间。
- 桌面版武装库常驻，窄窗口提供抽屉入口；历史记录从常驻顶栏进入，不因侧栏折叠而丢失。

## 验证证据

- 50 个改动前对局（覆盖全部新卡及轮换的 10 种增幅器）逐帧哈希对照一致；剔除新增观测字段后，伤害、生命、屏障、发动、状态、弹道与日志保持原样。
- 自动测试包含放置与移动原子性、邻接及优先目标、统计与档案摘要对账、持续伤害归属、真实被动联系、无效修复、回看状态及旧档案兼容。
- 浏览器实际走通桌面布阵、满编、增幅器选择、灼烧战斗、暂停与恢复、档案重建、移牌、再次对局、路线与装备复盘及全屏。
- 141 项自动测试、TypeScript、lint 通过；生产静态构建通过。浏览器错误日志为空。
- 实际检查普通桌面、全屏与 800×900 窄窗口；武装库、详情与档案入口均可用。测试阵容从首局获胜调整为次局失利，父局比较正确保留移牌、移除装备、生命与时长的变化；不据此推断普遍强弱。
- 这些检查不等同于新玩家理解或卡池平衡验证。

## 假设与待验证项

- 假设统一空间与实际因果提示会帮助玩家读懂组合，并改善下一局调整；仍需用户试玩和独立玩家验证。
- 极高触发密度下，短反馈的数量与持续时间仍需按试玩校准。事件明细保留全部记录；战场只展示最近的有限条提示。
- 物件外形属于可用表现基线，精制材质、独立动作和音效仍可继续深化。窄屏支持点击操作，手机原生拖放和低端显卡表现尚不能作为已验证承诺。

## 范围与兼容

正式冒险、物品获取、数值平衡和三路规则不变。页面档案保持 v1 输入格式，不迁移或覆写冒险存档。未把此迭代视为正式冒险已全面接入 3D 的证据。
