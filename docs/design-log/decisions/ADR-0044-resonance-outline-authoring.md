# ADR-0044：先共同完成故事大纲，再选择游戏表现形式

日期：2026-10-04。产品：共鸣卡牌 `apps/resonance`。

## 用户决定

先共同完成故事大纲，再决定游戏表现形式。项目网站需要新增「大纲编排」入口，让用户和助手可以在网页上维护、撰写大纲。这并未批准上一轮建议的横向小场景、JRPG或其他表现形式。

## 实现选择

- 首页顶栏、开篇与旅途手记提供 `/outline` 入口。
- 「世界与主线」「章节大纲」「待讨论问题」分别记录故事骨架、情节顺序、分歧与结果；提供全文通读。
- 现有剧本作为七章初始草稿；情节点与章节可增删、上移下移。草稿／待讨论／已确认只记录共同讨论状态，不代表对白已进入游戏。
- 当前本地开发服务自动保存到 `apps/resonance/src/outline/outline.json`。助手后续读写同一文件，必须保留稳定标识与版本，不从旧剧本文档覆盖用户已写的内容。
- 浏览器留存草稿，提供撤销／重做、大纲JSON导入导出、Markdown阅读文稿。项目保存使用版本比较和原子文件替换，冲突时让用户选择，旧版本留在同目录 `.outline-history/`。
- 本地保存适配器只在本机开发服务开放；静态发布页面明确使用浏览器草稿，并通过导入导出交换。不把本地功能宣传为云端多人协作。
- 大纲与战斗配置分离。编排不会自动修改玩法、现有对白或回放版本；之后按确认的章节另行同步。

## 区分事实与待定

音乐治愈心魔、温馨冒险、保留玩家编曲与非对称敌群为用户已定方向。阿弦、沿途人物、听风会与章节结构为创作草稿。母亲离开原因、贯穿旅途的目标、主角的错误与转折、完整主线和重复单局的关系、最终表现形式均待讨论。
