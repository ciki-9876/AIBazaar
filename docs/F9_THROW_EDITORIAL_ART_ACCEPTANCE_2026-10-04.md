## 本轮迁移的目标

将目前可控横版魔术师冒险和甩牌战斗的表现转为柔和色块、平滑轮廓、印刷纸张界面。人物、场景、道具、扑克牌、任务、对话及字体需像同一作品，不能只把深青 UI 换成奶油底，继续展示旧像素人物或旧物品 ICON。

保留上一轮已正确建立的独立资产、人物／家具共同尺度、运行时受光、身体横向锚点与脚底基线。已有剧情、行走／建筑／对话流程及 `throw-duel-v3` 的数值、随机流与胜负结果保持。

录屏中的经营资源栏有较高图标密度。可迁移其材质、层级与图形风格；本 RPG 只展示自身需要的任务、地图、出牌和整备信息，不照搬整套经营系统。

## 1. 界面与任务

- 常驻栏采用奶油纸或暖灰底、墨灰／深棕文字、有限的砖红／蓝色重点；背景噪点不能使正文难读。
- 中文正文和数字使用清晰、平滑的字体；标题可以具有报刊或舞台节目单气质，正文和按钮优先可读。字体组合是本项目自己的选择，不宣称精确辨认了录像中的字体。
- 当前任务只表达目标和下一步行动；重点卡片的色彩、标题或肖像足以识别，不依赖反复长段说明。
- 短 NPC 交流可用贴近人物的纸质气泡；长剧情或邀请函仍可使用阅读弹窗。两者具有共同的纸张、墨色与字号层级。
- 静态界面图标以清楚单色或有限色块为主，描边和边框尺度统一；不能所有按钮都用金属高光、厚重金框或发光胶囊。
- 字号按实际视口验证：桌面主要正文建议不小于16屏幕像素、窄窗不小于14；这些是助手首版可读门槛，不是录像测量。
- 主动作、次动作和不可用状态分辨清楚。选择不会先执行，确认按钮执行真实行动；不要为模仿参考改变原有整备／遗物提交语义。

**否决条件**：中文仍为方块像素字或出现缺字；任务卡占满场景；整屏并列同等亮度标签让玩家找不到当前行动；正文与纸底对比不足；场景换成插画但任务／对话保留旧深青像素面板。

## 2. 场景与建筑

- 色块是主构造：赤陶、奶油、墨蓝、木褐、低饱和青绿可组成基础色域；丰富感来自轮廓、局部体积、冷暖和生活细节，不来自写实毛孔或满屏噪声。
- 近景建筑、室内家具、远景与天气能独立摆放；同一门、窗、灯、桌或饰物可复用和替换，不回到包含人物与全部光影的一整张背景。
- 外墙、地板、家具边缘在镜头移动时平滑且稳定；不得沿用放大原生像素网格、最近邻锯齿或 CSS `image-rendering: pixelated` 作为最终风格。
- 场景内容明确服务地点：工作室应有魔术道具与修理／教学生活痕迹，剧院有舞台与节目单语言；不把报社家具原样搬入所有地点。
- 大面积留白具有构图作用，但不能让主要场景像少量贴图摆在空盒子内。新增细节必须仍是可复用资产，不用杂乱纹理填满墙。
- 角色前方的可达地面连续，建筑热点落在可见入口位置。前景遮挡允许增加层次，但不能盖住角色脸、脚底或当前交互对象主体。

**否决条件**：角色／家具／墙面三种不同画风；背景比角色精细一个量级；人工几何底图和生成物件拼贴边缘明显；虚假门口与实际热点分离；为展示整幅画把人物缩成小人。

## 3. 尺度与人物

尺度沿用已验证的世界比例，独立于这轮是否继续使用某个低分辨率画布。成人基准为192世界单位，工作室门264、桌108，分别为1.375倍和0.5625倍。若美术重新裁切，按可见轮廓高度核对，不能把透明留白算进人物身高。

- 成人体型与参考接近：四肢有长度、躯干能读出衣物结构，面部以少量形状表达情绪；可适度可爱化，但不能回到幼儿大头或像素动漫脸。
- 主角的红围巾／深青外套、导师的浅发／眼镜／背心、机械师的工装、竞争者的讲究衣着保留辨识度。变化来自原创人物设计，不复制参考人物脸、服装组合或名字。
- 人物外轮廓以色块和有限的内线表达，不使用整个人物厚黑描边；肤色、衣物与场景能在暖灯下自然统一。
- 门口、桌边、NPC并排三种位置都要截图。桌面约在腰部，桌椅与脚底共地，室内外人物可见身高相同；不在进门时任意放大或缩小主角。
- 待机应体现呼吸、眨眼或衣物轻微变化。行走体现摆臂、落脚和围巾的二级运动，不能只是将站姿图片平移。
- 帧矩形与身体／脚底锚点明确。连续换帧、转向、启停和对话往返不跳位、不缩放、不漏相邻帧；保持表现时钟在确定性规则之外。

推荐至少保留8帧主角步行及独立NPC待机帧；数量不能代替姿势正确和实际流畅观察。NPC只有待机时必须按待机描述，不宣称NPC行走已经实现。

**否决条件**：面部和身形每帧变人；AI图集含相邻人物残片；脚底在启停／左右翻转时漂移；主角走路像纸片晃动；NPC帧动画依赖玩家走路才更新。

## 4. 道具、扑克牌与战斗

- 场景道具、整备图标和道具效果提示共享柔和插画语言。旧像素药箱／灯／茶壶与新人物同时出现，即视为未完成替换。
- 小物件优先读清外形：一眼区分箱、灯、壶、瓶、钟等，压低内部细节；状态信息用数值／图标叠加，不画进不可修改的图像。
- 扑克牌保持红黑花色与清楚点数；平滑纸边、有限墨色、适当纸质层次，避免厚塑料金属卡壳。选中、飞行与命中是同一张牌的形象。
- 核心数值继续粗而清晰。描边、花色和数值不因仿印刷设计而变细变暗；字体风格变化不能改变伤害与效果语义。
- 左右战斗布局中，手牌／待甩区、己方、敌方和命中方向构成可理解的动线；一次甩牌能追踪到实际敌人，动画起点不能脱离选中的牌。
- 道具发动名称与动画在相关位置出现，同时触发多个效果仍可分辨。战斗焦点来自这次出牌与命中，不由一排永远发光的道具抢占。
- 10格整备、物件尺寸、位置联动和单遗物装备流程保持；不以换皮更改牌型倍率、冷却、伤害类型或布局规则。

**否决条件**：新界面中仍大量出现旧像素道具；纸牌飞成另一种图片；伤害数字／花色难辨；左右改排使人物、牌区或按钮被挤出页面；布阵拖放与装备提交行为改变而没有相应规则决定。

## 5. 灯光与动效

- 维持实际运行时灯光：灯芯有局部亮点，灯下／邻墙形成有方向的暖色受光，冷窗产生另一种光色；移动人物和家具进入同一受光计算。
- 参考的软光可以启发光形，但不能直接把参考帧的光锥作为素材粘进游戏，或以固定 CSS 发光圈声称动态光照。
- 插画轮廓保持平滑，光照不能再次在低分辨率网格上形成肉眼明显的大色块阶梯；如采用低分辨率光照缓冲，应平滑合成并检查与高清物件关系。
- 暖灯靠近／远离、朝向变化、镜头移动时，照明位置与角色位置一致；正常暗处仍能辨认脸和衣物，不使主角消失。
- 卡牌飞行、人物启停、框选和道具反馈观察连续过程，不把静态截图等同流畅性证据。
- GPU正常路径、CPU回退和性能记录分开。未强制测试的回退不标通过；没有测量帧率时，不写“稳定60 FPS”。

## 6. 浏览器验收操作

建议覆盖1920×1080、1280×720、1024×600与390×844。以下是待执行计划，不是已测列表。

1. 从开场进入街道，检查常驻任务、字体、人物和建筑是否共同采用新风格。
2. 主角左右行走两个循环，停步和快速转向；分别在门边、灯下与暗处截图。
3. 进入工作室，站在门／桌／导师附近，比较可见尺度和暖冷受光；与导师对话，检查短句和选项。
4. 开始实际导师练习，检查整备拖放与遗物弹窗、红黑扑克牌、左右战斗、牌飞至敌人、命中生命更新、道具效果名称与动画。
5. 按真实胜负返回场景，核对原位置、正确对白和邀请，不注入隐藏状态或剧情必胜。
6. 与米娅对话，进入剧院与菲利克斯对话，打开关闭地图，核对新人物和任务／地图风格。
7. 各视口核对页面无横纵溢出、正文和行动按钮完整可见；画布聚焦和对话聚焦不引起场景滚走。窄窗即使响应式重排，也必须保留清楚的出牌动作和敌人。
8. 最终fresh reload后观察控制台；记录实际正常渲染器、加载状态和仍未验证的回退路径。保存实际游戏截图，参考关键帧只用于比较。
